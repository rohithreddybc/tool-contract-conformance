# Do Agent Benchmarks Do What They Say?

**Subtitle:** An Executable-Contract Audit of Tool-Using Agent Environments

Rohith Reddy, Wenbin Zhang

## Abstract

Autonomous agents that call external tools are moving into consequential settings, including clinical decision support, where a wrong action carries a real cost. The benchmarks that measure whether an agent is ready for that responsibility score it by executing tool calls against a simulated environment and grading what those calls report having done, as changed state or as returned results: existing evaluation checks that a tool reported success, not that the state it describes actually changed. None of the audits we survey test that assumption; they inspect tasks, gold solutions, and graders, never the tool implementation, so a benchmark whose tool silently no-ops can report the same success as one that behaves correctly. Benchmark scores are published data that the field aggregates into leaderboards and consumes in model-selection decisions. A defect at this layer therefore does not average out: it is present on every rerun. Whatever exposure it creates travels with the number into every downstream use. We close this gap by authoring executable contracts from each tool's advertised surfaces (docstring, schema, prompt text, return value), checking implementations and state transitions against those contracts with a static and dynamic checker, and tracing which task verdicts depend on state a defective tool should have written. Across four benchmarks we confirm four headline-eligible tool-layer defect cells, from eight verified instances: three demonstrated dynamically and one, MedAgentBench's Phantom Effect, statically. Its interface tells the agent that each write executed. MedAgentBench's own paper documents a no-write design that the interface never discloses to the agent; no grader reads the record back, and where a write oracle exists at all it reconstructs the write from the agent's own transcript, gated on that unqualified success string. Score-at-risk bounds are basis-tagged rather than pooled: an exact-field evaluator puts 1,135 of 2,285 tasks in tau2's full generated telecom file (not its own smaller published-evaluation subset) at risk, while a coarser whole-database-hash basis puts all 50 airline tasks at risk by construction. Detection on the mutation arm is precise (≥0.867, zero false positives over 25 flags) but recall is weak, likely underpowered, at design-effect-adjusted Wilson lower bounds on real tools; an open-world mutation arm gives an escape rate ≥0.956 on a toy domain and an undefined rate, zero live mutants, on tau2. A pre-registered (scope: §IX) trajectory-replay check on ten gold trajectories exercises the defect zero times and records zero verdict flips.

## I. Introduction

<!-- Restructured 2026-09-04 to mirror the abstract's five-part order in four paragraphs

Agentic benchmarks help decide which language models ship, and the agents those models power are moving into settings where a mistaken action carries a real cost: managing a patient record, executing a financial transaction, or committing a change to a production codebase. A benchmark scores an agent for that responsibility by executing its tool calls against a simulated environment and grading what those calls report having done, whether by reading the state they left behind or by reading the results they returned, assuming in either case that each call did what its interface said. That assumption sits underneath every leaderboard position and model-selection decision built on such a benchmark's number.

That assumption is fragile: LiveClawBench names, as its motivating problem, that agent-benchmark mocks are commonly "reduced to endpoint-level stubs that remove sessions, artifacts, state transitions, and downstream side effects" [liveclawbench26]. This is a prospective observation, not a measurement of which shipped benchmarks discard state transitions or what that costs their scores. The benchmark audits we survey examine task instructions, gold solutions, evaluation scripts, environment configurations, graders, and judges [benchguard26], [aba26], [toolveritas26], [safeaudit26]; each of these stops one layer above the tool body and treats its implementation as ground truth, so a grader inspecting sandbox state inherits any defect in the tool that wrote it, and reports agreement. None of these tests the interface-to-state-transition contract itself; §II maps their categories.

One shipped benchmark exhibits the divergence directly. MedAgentBench [medagentbench25] evaluates language-model agents against a simulated electronic health record, and its paper documents a deliberate simplification: only GET requests reach the environment, and a POST instead receives a JSON-loadable sanity check after which the harness "indicate[s] success of execution to the agent system" (§2.4, §2.4.3 of that paper). Nothing the agent reads carries that disclosure. The prompt template states call syntax only, and the tool schemas are translated from the FHIR API. The branch handling every write (`src/server/tasks/medagentbench/__init__.py`, lines 85–91 at commit `9926011`) parses the payload into a local variable, never reads it again, and injects into the agent's transcript the unqualified string "POST request accepted and executed successfully," the worked instance Figure 1's caption walks through. No code anywhere in the repository performs the write: `git grep send_post_request` returns nothing at the pinned commit, and every `requests.post` call site sits in the client-side model transport instead (verified in `FINDINGS-VERIFIED.md`, shipped in the artifact). The defect this paper reports is therefore not the missing write, which the maintainers chose and documented, but the agent-visible claim that it happened. The benchmark's own write-task grader then relies on that claim as its evidence of record.

Benchmark audits inspect bands 1 and 3 only. We set out to test that interface-to-implementation-to-state-transition contract directly, for every mutating tool a benchmark ships, and three things make that hard. First, no formal contract exists to check against: one has to be authored from the tool's own advertised surfaces, docstring, schema, prompt text, and return value, and a check built against a surface that is itself wrong inherits the error. Second, a benchmark's simulated environment is deliberately simplified in ways its own maintainers consider harmless, so a checker flagging every departure from a naive reading of the interface would drown real defects in noise. Telling a disclosed simplification from an undisclosed one therefore needs a principled rule, not a maintainer to ask. Third, a violation in a tool's contract does not by itself say which published task verdicts it could have corrupted; that requires tracing the defect through the benchmark's own evaluation code, written independently of the tool, to the specific fields the defect reaches.

That untested contract is also a data-quality problem of direct concern to this community: benchmark scores are a published data product that the field mines, aggregates into leaderboards, and consumes in model-selection and deployment decisions, the context the data-quality dimensions literature judges a data product against [wangstrong96]. This paper audits that provenance, tracing which verdicts depend on state a defective tool produced, the same dependency analysis provenance research formalizes for a query [bunemantan01]. A defect in that instrument is, unlike noise, present on every rerun, so the exposure it creates travels with the number into every downstream use. What that exposure could amount to is what score-at-risk bounds, without asserting that any verdict changed. Auditing the process that generates this data is data-quality and data-lineage work in the most literal sense.

This paper meets those three challenges directly. For each mutating tool in a benchmark, we author an executable contract from the tool's own advertised surfaces (docstring, schema, prompt text, return strings). We then check the implementation and state transitions against that contract with a static and dynamic checker, and trace which task verdicts depend on the state the defect corrupted, tagging each bound by the evaluator basis that produced it. The contributions, in order of importance:

1. **Score-at-risk dependency analysis**: a static, per-benchmark bound on how many task verdicts depend on state a defective tool should have written, each row tagged with its evaluator basis (§IV).
2. **Six executable defect classes** over the state-transition contract, defined as checker rules rather than prose (§III). Phantom Effect, Partial Effect, and Reset Leak have no counterpart in any surveyed audit taxonomy.
3. **A provenance-bound contract format** in which every clause cites the advertised surface it operationalizes, and a static plus dynamic conformance checker (§V, §VI).
4. **Open-world validation of detection**: precision and recall against both taxonomy-shaped and off-taxonomy injected defects, under a pre-registered plan (§VII).
5. **Confirmed findings**: four headline-eligible benchmark-class defect cells across four shipped benchmarks, from eight verified instances, each read directly at a pinned commit by someone other than whoever surfaced it, with coordinated disclosure to all maintainers (§VIII).

The checker's role in these findings is confirmation and score-tracing rather than discovery: §VIII's Surfaced-by column shows seven of eight findings surfaced manually and one by static check. The paper's claim rests on the audit result and the criterion behind it, not on the checker having found the defects first. We did not invent design by contract, contract inference, or benchmark auditing either: §II concedes the technique and rests our novelty on the target and the consequence for published scores. The rest of this paper proceeds as follows: §II surveys prior benchmark grading, completion-verification, and contract-testing work; §III fixes the notation and the defect taxonomy; §IV traces score-at-risk dependencies; §V and §VI present the contract specification and the conformance checker; §VII validates detection; §VIII reports the audit findings and coordinated disclosure; §IX examines threats to validity; and §X concludes.

## II. Background and Related Work

Figure 1, introduced in §I, already carries this section's positioning claim: every audit adjacent to this one stops one layer short, or points its contract the other way. Three families examine only the artifacts above the tool body (task instructions, gold solutions, evaluation scripts, environment configurations) and treat the tool's implementation as ground truth; a fourth family applies contract vocabulary but keeps the contract itself as the trusted input and the agent as the system under test, the opposite direction from this paper. The table below disposes of each by name, with the two that share this project's own audited artifacts (the checklist that already names a tau-bench defect, and the construct-validity literature's genre of judgment call) given the fullest treatment, since a reviewer of either would ask first whether we duplicate it. The structural point is common to all of them: a tool that returns success without acting is invisible to an audit of task artifacts or of agent-side contracts, because the artifacts or contracts they inspect remain mutually consistent with each other.

AgentFairBench makes the same move for fairness measurement: it observes that fairness is still assessed by grading answers while agents increasingly act, and it scores those actions with metrics that include a tool-invocation disparity [agentfairbench26]. Measures of that kind read the tool layer directly, so they inherit whatever it gets wrong.

**Contract inference and API oracles.** One line of prior work establishes mature contract-checking and oracle machinery for specifications and implementations in general, but none of it targets the tool-to-agent boundary this paper does. Design by contract with runtime verification is decades old [jcontractor05], [jass01]. Contract inference, oracle languages, and invariant detection already cover much of the surrounding ground: implicit API contracts over pointer state, with 127 developer-confirmed inconsistencies [contract26]; a first-order executable contract language [icepick26]; REST invariants at 80% reported precision [agora25]; frame specifications for what a call must not change [frames25]; and contracts synthesized for stateful modules [cogent23] or studied for deep-learning APIs [dlcontract23]. Our Ignored Argument and Partial Effect detectors are metamorphic relations in all but name [segura18], [segura16], [chen18], and stateful sequence exploration is established for REST APIs [restler19], [godefroid20]. None of this line examines an agentic benchmark harness, and none of their fault models contain a success signal decoupled from state, an effect applied without its inverse, or state leaking across episodes. What distinguishes this work is the cost of a fault: in production it costs an outage; in a benchmark it costs a number nobody can tell is wrong.

**A second lineage: agents and benchmarks as the target.** Kapoor et al.'s critique of agent-benchmark evaluation practice [kapoor24matter], BetterBench's benchmark-quality rubric [betterbench24], and UTBoost's test-oracle hardening for SWE-bench [utboost25] all audit a layer above the tool body, and none contests this paper's novelty claim. PolDet [gyori15] and iDFlakies [idflakies19] anticipate Reset Leak via a comparable oracle; Reset Leak is mutation-only with zero field instances here, so conceding this precedent costs nothing beyond narrowing its novelty to target rather than technique.

**The published numbers this defect sits under.** MedAgentBench's paper reports "Action SR", the write-task success rate, for all 12 evaluated models in its Table 3 [medagentbench25]: it ranges 0.00% to 71.33%, best Gemini-1.5 Pro, two models at 0.00%. The abstract headlines 69.67% overall SR for Claude 3.5 Sonnet v2, a weighted blend of Query SR and this same Action SR. The number the authors foreground therefore inherits the construct-validity problem for its write half. We cite the arXiv table, read directly; the same paper is published in NEJM AI (vol. 2, iss. 9), evidence these numbers reach a clinical audience. The file containing the POST branch of §I has been touched by exactly one commit (January 2025) and is unchanged at our pinned commit, so every Action SR value was produced under an implementation in which no write occurs. The paper's own §2.4.1 describes "rule-based sanity checks to verify the correctness of the payload of POST requests": the transcript-reconstruction mechanism §VIII traces, gated on the fabricated success string. To be precise: the numbers are not wrong. They faithfully measure whether the agent emitted a well-formed POST request, not whether any clinical record changed. The disclosure sits in the paper's evaluation section, not in the label "action success rate" a leaderboard reader sees.

**A single-layer audit finds each layer consistent here.** The tool defect (Finding 1) and the grader design (Finding 4) are mutually consistent: the grader's gate condition is the literal success string the harness injects at `__init__.py:91`, consumed by `extract_posts`. The tool therefore reports a write that did not happen, and the grader accepts exactly that report as its evidence. Audited alone, each layer is coherent. The tool returns what it says it returns, and the grader correctly detects what it looks for. BenchGuard's EVAL-MISMATCH category and Tool-Veritas's reward-basis mismatch are the nearest categories on the grader side; neither schema has an entry for a success signal decoupled from state, so neither could report this instance whether or not it were run on this benchmark. Single-layer audits are blind to cross-layer consistency defects by construction, insufficient when the layers agree with each other about a world that does not exist. That the benchmark's own paper documents the no-write design (§I) changes nothing here: an audit of task artifacts reads what the artifacts say, and the artifacts agree. We distinguish Ungrounded Oracle (§IV) from Tool-Veritas's reward-basis mismatch: theirs concerns whether the verdict matches the outcome, ours the provenance of the oracle's evidence. JudgeSense reports a comparable evaluator-layer fragility one step higher in the stack: LLM judges are unstable under meaning-preserving prompt rewording, with coherence the dimension separating judge behaviour most and the largest, newest models not the most consistent [judgesense26].

**tau2-bench's numbers.** The pinned commit we audit sits inside the code lineage that produced tau2-bench's own published per-domain pass^1 results and the numbers on the live public leaderboard linked from the repository's README, and both audited defects have been present, unpatched, across that entire span [tau2bench25] (`EXTERNAL-VERIFICATION.md` Task 2). We claim no causal link from either defect to any specific published tau2 number here. Whether a task verdict depends on the affected state is exactly the question the score-at-risk analysis of §IV exists to answer, and asserting it from outside that analysis would overreach.

The field's own newest benchmark work names our symptom while auditing nothing [liveclawbench26]; §I already states what is new here (the target and the traced consequence for published scores), so this section does not repeat it.

## III. The Benchmark Tool Layer as a Measurement Instrument

A benchmark tool is not application code that happens to be simulated; it is the write path of a measuring device, and a defect in one enters a published number silently and on every rerun rather than filing an issue, with the corrupted number still cited either way. This section fixes the object under test, the defect classes, and the principle that separates a defect from a legitimate simplification.

**Why the defect is invisible downstream.** Every deterministic evaluator in the surveyed literature reads state that tools wrote (tau2-bench's own evaluator compares final database state between gold and predicted runs, §IV), so a defective tool's output is inherited by any gate reading it (§I, §II). Consistency between a broken tool and a grader reading its output is not validity; that is why the tool layer needs its own audit rather than better downstream checks.

**The defect taxonomy.** Table I defines six defect classes, each as an executable checker rule over the tuple `(pre, post, args, result)`: the canonical state snapshots before and after a call, the call's arguments, and its return value. The classes are typed at the tool boundary. Prose descriptions are glosses; the rule is the definition.

**Table I — Six executable defect classes.**

| Class | Checker rule (over `pre`, `post`, `args`, `result`) | Contradicted surface | Status |
|---|---|---|---|
| Phantom Effect | success signal true ∧ advertised effect delta absent | success signal, effects | field-observed |
| Unenforced Precondition | precondition predicate false ∧ (no error signal ∨ state mutated) | preconditions | field-observed |
| Ignored Argument | post-state invariant under variation of an argument advertised as effective | signature, effects | field-observed |
| Partial Effect | ≥1 advertised effect predicate holds ∧ ≥1 fails on the same call | effects, frame | field-observed |
| Invariant Break | environment invariant false after a legal call sequence | invariants | mutation-only |
| Reset Leak | snapshot after reset ≠ initial snapshot | reset | mutation-only |

Four of the six classes are field-observed in shipped benchmarks (§VIII). Invariant Break and Reset Leak have no field-observed instance anywhere in our findings: they exist only as injected mutants, and every count in §VII and §VIII keeps that distinction visible. We note the direction of travel rather than hide it: Ignored Argument was itself mutation-only until the third and fourth benchmarks were audited, and it is now the most common class in the finding set, with four instances. Breadth of audit, not depth on one artifact, is what converted it. The taxonomy has an anchor lineage worth stating plainly: all six classes were carved from the tau2-bench and MedAgentBench anchor findings before AgentDojo and MM-ToolSandbox were audited, so the classes fit the defects that produced them by construction, and §VII's open-world escape rate measures exactly that circularity rather than closing it.

**Result–state disagreement is a signal, not a class.** The Ignored Argument rule is deliberately state-only, since a conjunctive post-state-and-result rule fails on a real case: AgentDojo's `reserve_car_rental` discards `end_time` from state but interpolates it into the success string (§VIII, Finding 6), which would leave one of the checker's own anchor findings undetected. A result that varies with an argument whose effect on state is absent is reported instead as an aggravating signal on the finding it accompanies.

**The benign-simplification principle.** The strongest objection a maintainer can raise is that these are intentional simplifications of a simulation that never claimed fidelity; telling that case from an undisclosed divergence, the second challenge §I raises, needs a criterion rather than a case-by-case judgment call, stated once and applied uniformly:

> A simplification is benign exactly when it is advertised. The defect is never the simplification; it is the undisclosed divergence between what the interface tells the agent and what the implementation does.

Three consequences follow. First, tau2-bench's own maintainers already draw this line: at `airline/tools.py:689` they advertise a deferred flight-database update in the surface the behavior is visible from, and the checker correctly does not flag it, while at line 367 they merely log that seat release is not implemented, in a warning the agent never sees, and the checker flags it. The distinction between disclosed and undisclosed divergence is theirs before it is ours. Second, either side of a divergence may be repaired: a maintainer who fixes an aspirational docstring restores conformance exactly as completely as one who fixes the code, and §VIII counts such a response as a resolved finding, converting the audit from an accusation into a specification of what disclosure would make a simulation honest. Third, the advertised surface is the right baseline against the position that a benchmark owes fidelity only to itself, because the agent's behavior is the measured quantity and is conditioned on the interface text. That baseline is scoped to one audience, however: **agent-side measurement validity**, the surface this paper audits throughout. It says nothing about **consumer-side label validity**: whether the leaderboard reader, who sees no docstring, draws the correct conclusion from a published score. The line-689 update is a true negative under our criterion precisely because the agent sees it; whether any score consumer does is a different question, one this paper touches only where MedAgentBench forces it: a design disclosed in a paper and on no surface the agent reads is flagged by the same rule that clears line 689 (§I, §VIII).

**One evaluator-layer property, kept outside the taxonomy.** MedAgentBench's write graders exhibit a property we name Ungrounded Oracle: the evaluator's oracle for a state change reads the actor's claim rather than the state. It is field-observed in §II, but it is not a seventh class: the six classes are typed over `(pre, post, args, result)` at the tool boundary, while oracle grounding is typed over grader source code, a different object entirely. §IV emits it as a per-task classification of the benchmark's evaluator rather than as a row in Table I.

## IV. Score-at-Risk Dependency Analysis

The paper's central deliverable is not a violation count but a trace: given a confirmed defect, which task verdicts could have been computed on state that defect corrupted. `analysis/score_at_risk.py` performs the trace as three static steps, no model anywhere in the pipeline, over the 1,208 rows written to `report/score_at_risk.jsonl`. A `--verify` flag re-derives every row from the same pinned inputs and diffs it against the file on disk, so the trace is checked before it is trusted, not merely reproducible in principle.

*[Figure 2 — the worked tau2 dependency graph: `cancel_reservation`'s `eff.seats_released` clause, the `post.flights.*.dates.*.available_seats` path it fails to restore, the whole-database hash that reads that path, and the 50 airline tasks the hash mechanism marks at risk by construction. Draft alongside the final Table II render.]*

**Step 1, defect to field.** From a contract's VIOLATES clause, the predicate's own compiled AST (never the predicate's source string) yields the state paths the tool should have written and did not, or wrote unconditionally when a precondition should have blocked the write. **Step 2, field to evaluator.** The benchmark's own evaluation code is parsed the same way, by AST rather than by pattern match, for the state paths it reads, and each read site is classified by provenance: does it read live simulator state, or does it read the agent's own transcript. **Step 3, evaluator to tasks.** Every task whose verdict depends on a field in the Step 1/Step 2 intersection is enumerated from the benchmark's own pinned task-definition file, exhaustively, with no exclusion.

Every at-risk figure carries a basis tag, and the tags are never pooled, a discipline scoped to score-at-risk denominators specifically; the detector-validation arm of §VII pools toy and real sites by design and is not covered by this rule. Reporting dimensions separately rather than as a single aggregate exposes failures an aggregate hides, a discipline RISED applies to clinical decision support, where reliability can pass while inclusivity and sensitivity fail [rised26]. tau2's airline domain grades `cancel_reservation` by comparing a full database hash between the gold and predicted runs (`toolkit.py:242-244`); any field a defective tool writes is, by construction, read by that mechanism, so all 50 airline tasks in the affected reward basis come back at risk. That is a measurement of the evaluator's coarseness, not of the defect's reach, and Table II tags it `whole_state_hash` rather than let it stand next to a sharper number. Telecom grades `refuel_data` through per-task assertion functions instead, and the intersection is exact: 1,135 of 2,285 tasks read a field the defective precondition lets through unconditionally, 1,120 of them on the specific written attribute (`exact_field`) and 15 more on the containing collection alone (`collection_only`). The 2,285 is the full task file generated at the pinned commit (`data/tau2/domains/telecom/tasks.json`), not the roughly 114-task subset tau2-bench's own paper evaluates per domain; `analysis/score_at_risk.py` has no mechanism to reconstruct that historical subset, so a published-evaluation-scoped count is not computed here. A single benchmark carries both bases on different tools, and no project-wide percentage is stated across them: only per-basis counts, each with its own denominator, since an aggregate score would conceal exactly this kind of dimension-level failure the way a passing benchmark verdict conceals a defective tool.

The bound runs in one direction only: at-risk is an over-approximation of misgrading via the state-dependency mechanism, and it holds only where the oracle is state-grounded. "Score-at-risk" borrows the shape of value-at-risk without its probability content: this is a static reachability over-approximation with no probability distribution attached, and the term should not be read as carrying one. It says a task's verdict could have been computed wrong because its evaluator reads a field the defective tool controls; it does not say the verdict was wrong, and it says nothing about failure modes outside that mechanism. §VII checks whether the bound is vacuous on a drawn sample and finds that, on the trajectories it recorded, it is not exercised.

**Oracle grounding, not a footnote.** A naive field-intersection returns the wrong answer for MedAgentBench, in the wrong direction: its write graders reconstruct the intended write from the agent's own transcript, gated on the fabricated success string of Finding 1 (§I, §VIII) — criterion contamination in measurement terms, the grading criterion contaminated by the very predictor it is meant to check. Field intersection alone cannot see this: the field the grader checks and the field the tool should have written share the same name, so a rule that only asks whether names match would call nearly every one of the 300 cases at risk, the opposite error from the naive zero a state-only reading might otherwise produce. The real classification is computed per grader function from whether it calls the transcript-reconstruction routine, the live-state routine, both, or neither: of 300 write-tagged cases, 60 are graded unconditionally from the transcript, 90 read live state only to gate whether a write is required and then grade the write itself from the transcript, 150 have no write oracle at all, and zero are graded by reading the write back from FHIR state. Score-at-risk is undefined for the 60 and indeterminate for the 90, never zero, never inflated, a distinct verdict emitted by name: "oracle not state-grounded." The evaluator property is Ungrounded Oracle (§III); this classification is what makes it a result rather than an aside.

The experiment frame need not nest inside the at-risk population, and for Finding 5 the two sets are disjoint. `experiment_frame_subset_of_at_risk` is computed, not asserted, and it is `False` for AgentDojo's Finding 5, contrary to the natural expectation that a stricter selection rule (a task whose own gold solution invokes the defective tool) is always a subset of the field-dependency population. `update_scheduled_transaction` is broken on every argument at falsy values (`amount` at `0`, `date`/`subject`/`recipient` at the empty string, `recurring` at `False`), but `recurring` is the one argument for which a falsy value is a legitimate advertised input, which is why it alone carries task risk here: four tasks' gold solutions call the tool but only to vary `amount` or `recipient`, so none of them lands in the at-risk set field dependency computes. The two sets share zero tasks. The one task whose oracle does read `.recurring`, `UserTask6`, reaches that field through a different, non-defective tool, `schedule_transaction`, and is therefore at risk by the field-dependency rule and outside the experiment frame by the gold-invocation rule. Argument-specific defects make the two rules select different, non-nested populations by construction: field dependency cannot see which argument path a task exercises, and gold-invocation cannot see which field the oracle reads. The relation is stated per rule, never assumed to nest, and both populations are reported with their own denominators.

**MM-ToolSandbox reports what it can compute and nothing it cannot.** Step 1 identifies the `sort_by` field `venmo_social` drops (Finding 7). Steps 2 and 3 do not run: the AppWorld-tier scenarios that exercise this tool are graded inside the `appworld` package, which this project cannot clone. Table II's row reads `not_computable_appworld_unreachable`, not a zero and not an omission. A null population is data about what a static, offline audit can reach, not a claim that no task is at risk.

## V. The Contract Specification

Every contract clause cites the provenance of the advertised surface it operationalizes (file, line, and a verbatim quote checked against the pinned commit at build time) across three grounding tiers: **agent-visible** text (docstring, schema, prompt template, tool return, README, external standard) the agent was conditioned on; **maintainer-annotated** text (a comment, log line, or TODO) stating intended semantics no agent ever sees; and **inferred** semantics we assigned ourselves. Only agent-visible clauses are headline-eligible (a violation there corrupts the measurement by §III's argument), while the other two tiers are reported separately and never folded into a headline count; this is the paper's construct-validity firewall against the objection that our contracts are just our opinions. The benign-simplification principle of §III governs contract authoring too: either side of a divergence may be repaired, a documentation fix resolving a finding exactly as completely as a code fix (§VIII). The checker also knows when not to fire: tau2-bench's advertised deferred flight-database update and its advertised non-enforcement of cancellation eligibility are both true negatives our test suite exercises, the credibility anchor behind every VIOLATES verdict elsewhere in the paper.

Contract authoring is measured, not trusted, but the measurement is of a narrower thing than independent replication. Both annotator sets, A and B, are agent sessions on the same underlying model family, and only B authored blind, since A already knew which tools carried confirmed findings; what follows is evidence of stability of sentence-to-predicate translation under one-way blindness, not of independent human judgment, and the paper claims no more than that. The two sets are compared extensionally against a shared, pre-committed probe corpus across six tools, over comparable clause pairs on successful calls only, a scoping rule landing in the same commit as the reported result (`dee7170`) rather than in the protocol itself (`fc776b6`), disclosed here as applied post hoc and unreconciled with protocol §6's rule that UNTESTABLE-vs-anything counts as a disagreement, never a skip: the exclusion is large, dropping `refuel_data` to n=2 of 9 probes and `reserve_car_rental` to n=2 of 11 on most clause pairs. The blind stratum agrees on 98 of 98 probe comparisons across 16 clause pairs, a span covering four of the five blind tools; the fifth, `venmo_social`, contributes zero comparable pairs, a segmentation artifact that also cost it Finding 7's own anchor `arg.sort_by`. Four tools (`refuel_data`, `cancel_reservation`, `update_scheduled_transaction`, `venmo_social`) needed hand-built witness probes, disclosed before any outcome was inspected, because the frozen corpus could not reach them. The sixth tool, `cancel_reservation`, separately forms a contaminated stratum (Annotator B had read a worked example of this exact tool beforehand) and is reported apart, never pooled with the blind result. One finding flips within the blind stratum: `reserve_car_rental`'s `arg.end_time` is VIOLATES under A and UNTESTABLE under B, a missing `probe_values` annotation pinning the argument to parseable ISO strings in B's contract rather than a disagreement about advertised semantics (mechanism in the artifact); both annotators independently flagged the underlying defect in their own notes. Full grammar and protocol detail are in the artifact.

## VI. The Conformance Checker

The checker has a static half (five AST-only checks that flag candidate sites for a person to read) and a dynamic half that produces verdicts: snapshot a fresh environment, invoke the tool, snapshot again, and evaluate every clause against the resulting `(pre, post, args, result)` tuple, resolving to CONFORMS, VIOLATES with a minimal witness, or UNTESTABLE with a reason code; UNTESTABLE stays in every denominator this paper reports. tau2-bench, AgentDojo, and MM-ToolSandbox run through adapters as subprocesses; MedAgentBench has no adapter and is checked statically (§I). All six defect classes now have a real dynamic or static code path, but four of them did not until a post-freeze mutation sweep exposed the gap. Reset Leak and Invariant Break verdicts, 35 frame clauses, and 17 of 19 tau2 contracts were silently never dynamically exercised. All four are fixed, at the cost of one disclosed refreeze cycle (`checker-freeze-v1` to `checker-freeze-v2`) rather than two. Adapter mechanics, the subprocess boundary, and the remaining frame-path expressiveness gap are in the artifact.

## VII. Detector Validation

This section's vocabulary and its logic of evidence come from mutation testing: inject a synthetic fault and check whether it is caught, using surviving ("live") mutants as a lower bound on what a test suite, or here a contract, misses [jiaharman11].

**What this checker demonstrably delivers today** is high-precision flagging (zero false positives across 25 mutation-arm flags) paired with a score-at-risk trace from a confirmed defect to the verdicts it could corrupt; coverage of the defect space remains the open problem §IX quantifies. The pre-registered plan fixes, before any mutant existed, what each arm can and cannot license (`experiments/detector_analysis_plan.md`, committed at tag `checker-freeze-v1`, commit `9dacc79`). The closed-world arm asks whether the checker detects a defect of a class we authored; a good result licenses the sentence "the checker detects violations of the clauses we wrote," never "the checker detects tool-contract defects." The open-world arm asks whether the checker notices a defect nobody designed for its taxonomy; a good result licenses only a lower bound on the taxonomy's incompleteness, never a claim of coverage. Every rate below is stated at its design-effect-adjusted Wilson lower bound (Kish design effect, Rao-Scott one-way ANOVA ICC estimator, per §5 of the plan) with its effective denominator printed beside it. The same discipline appears in clinical-agent auditing, where a counterfactual flip rate cannot be read as evidence of disparity unless a measured per-action instability floor is reported beside it [instabilityfloor26]. Toy-domain numbers, from the domain the checker's own authors wrote with this taxonomy in mind, are reported for debugging and never enter a headline; the headline is real-tools recall only, drawn from tau2-bench, AgentDojo, and MM-ToolSandbox.

Recall as shipped is low, and a post hoc diagnostic written after the corpus was scored, `experiments/decompose_closed_world_misses.py`, traces why: of all 33 real-tool misses, the taxonomy itself owns 2 (`clause_gap`), the frozen probe corpus owns 29 (`probe_corpus_unreachable`, never driving the mutated path into an observable state), and the remaining 2 are `probe_gap` and `target_not_found`. Two of these names are reused labels, not the pre-registered scheme itself: the open-world taxonomy pre-registers a three-way `clause_gap`/`probe_gap`/`canonicalization_gap` split, while this closed-world classifier is a different four-category schema whose dominant bucket, `probe_corpus_unreachable`, has no counterpart there — same underlying mechanism, different category set. The bottleneck sits in probe reachability, not in the six defect classes; the per-operator sub-breakdown and the watchdog-timeout exchangeability question are in the artifact. M-INVAR's 0.000, decomposed by liveness screening only (`operators_liveness_only`) rather than the full three-way classifier, reads as "no probe ever reached a mutated invariant path," not "the checker cannot detect invariant breaks." M-RESET has no real-tool site to draw at all: no tool-implementation file in any of the three real benchmarks defines a state-restoring function, so the honest report is "no data," not a rate of zero. Biconditional success (a contract clause asserting success only if every advertised effect holds, the mechanism M-PHANTOM's detector depends on) is opt-in per contract, adopted on 18 of 19 tau2-bench, 1 of 7 AgentDojo, and 0 of 5 MM-ToolSandbox contracts; where not adopted, Phantom Effect cannot fire at all: a second, more visible reason M-PHANTOM's recall sits at 0.359 rather than higher.

**Precision.** Zero false positives across every flag the checker raised against an injected mutant in the closed-world arm, on a pooled toy-plus-real sample of 25 flags (TP=25, FP=0; 24 semantics-preserving controls scored alongside): precision ≥0.867 at the Wilson lower bound. This denominator is mutation-arm flags only; it says nothing about the field findings of §VIII, which were confirmed by direct source reading, not by this count. This is the strongest number in the section, and it licenses nothing about the recall figures above: a detector that never lies about what it does catch can still catch very little of what it should, and it structurally cannot false-positive against a clause it never wrote, unlike the AGORA+ reference point of §II.

**Achieved N against pre-registered N.** Only M-PRECOND and M-IGNARG met the ~25-per-class target, counting real and toy sites together as the pre-registration's draw target does (the recall table above, by contrast, reports real-tool sites only, which is why its own n-drawn column reads 7 and 21 for these same two operators rather than 25). The rest reflect the plan's §8 no-reuse refreeze rule meeting a structurally small pool, not a scoring shortfall, detailed further under §IX and in the artifact.

**One refreeze cycle.** The numbers above are scored under `checker-freeze-v2` (commit `54b74d4`), not the first freeze: a mutation sweep against `checker-freeze-v1` found four taxonomy claims the checker had been carrying as closed with no code behind them, detailed in §VI, and the checker was refrozen before any number here was scored.

**Open-world escape rate, toy.** cosmic-ray scored 368 mutations across 4,048 (mutation, tool) pairs; 229 were behaviourally live, and the checker missed a Wilson lower bound of 0.956 of them (point estimate 0.983), decomposed as 119 of 225 escapes tracing to a clause the taxonomy never wrote, 86 to a clause whose probes never drove the tool into the exposing state, and 20 to the checker crashing before evaluation. Only the mechanical declared-volatile-field adjudication rule ran in this automated pass (the interface-invisibility and second-annotator rules both need a human annotator and are documented in the artifact), which makes 0.956 conservative in the direction of overstating the checker's blindness. Per the committed framing, this is a lower bound on the taxonomy's incompleteness, not evidence against the closed-world numbers above.

**tau2-telecom produced no usable escape rate.** cosmic-ray scored 465 mutations across 2,325 (mutation, tool) pairs against the domain's five non-anchor tools, and zero were behaviourally live, so the escape-rate denominator is zero and this arm did not run to a conclusion. The cause is the probe corpus, not the detector: its recorded-real-call component does not exist, and the two placeholder components fail existence checks on tau2's entity-keyed tools before any mutation could show (mechanism detail in the artifact). A zero denominator is not evidence of a well-covered taxonomy, and this arm is reported as an open question, not a result. A precompute cache built before `checker-freeze-v2` existed had already produced a v1 run on this same arm (281 of 465 mutations scored, 33 behaviourally live, escape rate ≥0.325), a more favorable number than v2's undefined rate, yet it is not reported as a result: the cache predated the v2 checker, so whether those 33 live mutants were genuine or artifacts of the stale cache is now unresolvable, and the run is disclosed rather than quietly dropped in the direction that would have flattered us to keep.

**Evaluation impact: a null, not a gap.** Two tau2-bench findings carry mechanically verified one-hunk patches: cancelling a reservation leaves `seats_after` at 0 unpatched and restores it to 3 patched; refuelling a suspended line succeeds unpatched and raises `ValueError` patched. Ten trajectories were replayed from each finding's own gold reference solution, five per finding (seed 1, zero discarded for infrastructure failure): agent trajectories were unavailable in this offline setting (no model credentials), so gold references were substituted, a disclosed deviation from the pre-registered plan (`experiments/analysis_plan.md` §§4–5). Per the plan's own determinism claim this is a strengthening, not a weaker substitute: no model selects the trajectory either, so the model is removed from the evidence path entirely, including at recording time. All ten land in a single outcome cell: at risk, not exercised, and zero trajectories trip either finding's trigger predicate, so zero verdicts flip. For F3 (airline `cancel_reservation`), no flip was possible by construction: the evaluator compares gold-run state against agent-run state, and both sides execute the identical, still-defective tool, so the symmetric-oracle structure absorbs the defect regardless of the exercise rate. For F2 (telecom `refuel_data`), a flip was possible in principle and did not occur, because none of the five sampled gold trajectories calls the tool on an inactive line. Per the pre-registered interpretation (`experiments/analysis_plan.md`), this is a finding about conditional validity, not a null result: the score is correct today because no gold reference trajectory happens to take the broken path, and nothing in the benchmark prevents an agent from doing so. N=5 per finding is provisional, with what that does and does not license taken up in full under §IX. Full experiment detail is in the deposited artifact.

## IX. Threats to Validity

**Taxonomy coverage.** The taxonomy is not the space of possible defects, and the open-world arm measures the gap rather than closing it. §VII's open-world arm on the toy domain found the checker missing a Wilson lower bound of 0.956 of behaviourally live mutants, decomposed there into unwritten-clause, unreached-state, and checker-crash causes. Six classes, even perfectly detected on the defects they name, would still miss most of what an operator with no knowledge of this taxonomy can break, the paper's own limitation, stated in its own numbers, not inferred from outside them.

**Real-benchmark escape rate.** The equivalent real-benchmark run produced no usable number at all, and the absence is reported rather than hidden (§VII). cosmic-ray's 465 mutations against tau2-telecom's five non-anchor tools yielded zero behaviourally live mutants, so the escape-rate denominator is zero; the cause is the probe corpus, not the checker. The same missing artifact (no production caller ever supplies a recorded real call) also explains the `reserve_car_rental` agreement flip (§V) and 29 of §VII's 33 real-tool misses, which makes a recorded-real-calls corpus this project's single highest-value piece of future work rather than a generic limitation.

**Sample size shortfall.** Sample sizes fall short of the pre-registration for four of six mutation operators, and the shortfall is structural, not a scoring choice. §VII's achieved-N table shows only M-PRECOND and M-IGNARG meeting the ~25-real-tool-site target; the rest exhausted a structurally small corpus under the plan's §8 no-reuse refreeze rule, not a scoring shortfall. Achieved N is reported beside the pre-registered target in every case, never silently absorbed into a rate.

**No real-tool reset site.** M-RESET has no real-tool site at all (§VII): reset logic lives in the adapter layer, which reconstructs environments wholesale rather than repairing them in place, so only the synthetic toy domain colocates reset with its tools for the operator to enumerate. The honest report is "no data," not a recall of zero, and Reset Leak's field-observed count anywhere in this project's findings is zero.

**Subprocess exception boundary.** The subprocess boundary absorbs exceptions the checker never sees, and whether that matters is unverified. A real bug on the toy domain during the closed-world v2 run showed the mechanism directly: an adapter's `invoke()` caught only its own declared error type, so a probe built to violate a deleted guard drove the tool past the missing check into code that assumed the check held, and the resulting raw exception aborted the mutant instead of registering as a violation. Toy is a debug domain and never enters the headline, but the same subprocess boundary sits between the checker and every real adapter, and it swallows arbitrary exceptions before the harness can classify them. Whether an absorbed crash on a real tool would score as a detected violation or a silent non-detection has not been checked, which bounds what every real-tools recall number in §VII means, a bound left unresolved rather than argued away.

**Provisional replay sample size.** The agent-experiment sample is provisional at N=5 per finding (§VII), and a null at that size proves less than it looks like it proves. F3's affected population of 7 tasks makes 5 close to exhaustive; F2's population of 1,120 does not. Zero of ten trajectories exercising either trigger predicate therefore cannot separate a defect latent under every gold trajectory from one an undersized sample missed.

**Anchor-driven benchmark selection.** Benchmark selection is anchor-driven, not a sample of a population. tau2-bench and MedAgentBench entered this study because their defects were already known before the four-benchmark protocol existed; AgentDojo and MM-ToolSandbox were added afterward to test whether the taxonomy generalized beyond the two anchors. No prevalence claim (what fraction of shipped benchmarks carry a given defect class, or how common Ignored Argument is across agentic benchmarks generally) is supportable from four benchmarks chosen this way. The four findings sets are existence proofs that the defect classes occur in shipped, audited artifacts, not a survey of how often they occur.

**Frame-grammar expressiveness gap.** The frame-path grammar cannot express one of its own most natural clauses. `spec/GRAMMAR-GAPS.md` records that no wildcard segment can exclude a single key, so a frame clause meaning "no other reservation is modified" cannot be written without also colliding with the tool's own advertised effect on the one reservation it is supposed to change. The shipped `cancel_reservation` contract substitutes a weaker, fully expressible claim about an unrelated collection, and the distance between the two is a real coverage hole in the frame mechanism, named here rather than hidden behind a narrower example.

**Repository history limits.** Repository history cannot support every ordering claim this paper might like to make. `git init` ran on 2026-08-21, after most of the design work already existed, and the first commit imported the project as a single tree. A squashed import cannot demonstrate that any pre-registration preceded the design decisions it was meant to freeze, and the paper does not claim that it does. What remains verifiable is narrower, and it is what the paper relies on: `checker-freeze-v1` predates the first scored mutant, and `experiments/analysis_plan.md` predates the first recorded trajectory, both checkable from commits made after the import. The distinction is stated here rather than left for a reviewer to discover (`PROVENANCE.md`).

**Disclosed refreeze cycle.** One refreeze cycle is disclosed rather than folded into the final numbers. §VI details the four taxonomy claims a mutation sweep against `checker-freeze-v1` found uncoded, all fixed before `checker-freeze-v2` scored any number in §VII. A framework that reports the sweep that found its own holes earns more trust than one presented as complete from the start, and the cost of finding them (one refreeze cycle rather than zero) is stated plainly rather than absorbed into the total. The other nine limitations above stand as stated, but not at flat salience: ranked by how much each could move the conclusions, the missing recorded-real-calls corpus matters most, since it alone explains the tau2 zero denominator, the agreement flip, and 29 of 33 misses; whether an exception absorbed at the subprocess boundary scores as a detection or a silent non-detection comes second, since it bounds what every recall number in this paper means; and the anchor-driven benchmark selection third, since it forecloses any prevalence claim.

## X. Conclusion

<!-- Compressed 2026-09-04 from two paragraphs to one, per MEETING-2026-09-02-WANG.md S9;
mirrors paper/latex/main.tex. Every claim and number retained. -->

This paper tested a layer the benchmark audits we survey do not reach: the tool implementation that produces the state a grader reads. Four benchmarks yielded eight verified instances across six executable defect classes, four of them headline-eligible under a grounding rule that excludes what no agent ever saw. The score-at-risk analysis traced what those defects could have cost in published verdicts, tagged by evaluator basis rather than pooled into one number, while the open-world arm measured how much of the defect space six classes still miss. None of this establishes how common these defects are across agentic benchmarks generally: four anchor-driven audits are existence proofs, not a survey, and the paper does not claim otherwise. Benchmark scores are published measurement data that the field mines and reuses in leaderboards and model-selection decisions, and an instrument defect at this layer propagates into every downstream use of the number it produced, so a score consumer should read an at-risk bound as a due-diligence flag warranting inspection, never as a correction to the published score itself. Maintainers can act on that asymmetry now: run a precision-favoring conformance check like this one against the tool layer specifically, not only against tasks and gold solutions; treat a flag as cause to look, not cause to re-score; and state every deliberate simplification on the surface an agent reads, not only in the paper that describes the benchmark, since on that surface an undisclosed one is indistinguishable from a bug to the agent conditioned on it and to the grader scoring the result. Never let a grader's success condition be satisfied by a string the harness itself fabricates, the pattern behind this study's most clinically consequential construct-validity failure; a benchmark's published numbers are only as trustworthy as the layer nobody has been checking.
