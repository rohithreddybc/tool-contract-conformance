\begin{abstract}
Tool-using agents are entering settings where a wrong action carries real cost, and the benchmarks certifying them execute each call in simulation and grade what the call reports, assuming the tool did what its interface advertises. The audits we survey inspect tasks, gold solutions, and graders, never that assumption. A benchmark score is a published data product, and a defect beneath it is present on every rerun, so the exposure it creates travels with the number into every reuse. We treat each tool's advertised surfaces as an executable contract, check the implementation against it, and trace which task verdicts read state a defective tool should have written. Across 34 mutating tools in four benchmarks we confirm eight defect instances at pinned commits, one headline-eligible class in each, meaning one visible to the agent. Against injected defects the checker raised no false positive in 25 flags pooled from toy and real sites; its recall is low, and 29 of 33 misses trace to the probe corpus that drives the tools, not the taxonomy. The clearest case is a clinical benchmark whose interface tells the agent each write executed, under a no-write design its paper documents and its interface does not. Its grader takes that message as evidence, so its action success rate records whether a request was well formed, not whether any record changed. Two repairs follow: disclose a simplification on the surface the agent reads, and ground a write grader in state rather than in the tool's own success string.
\end{abstract}

\section{Introduction}
\label{sec:intro}

Agentic benchmarks help decide which language models ship, and the agents they power are moving into settings where a mistaken action carries a real cost: managing a patient record, executing a financial transaction, or committing a change to a production codebase. A benchmark scores an agent by executing its tool calls against a simulated environment and grading what those calls report having done, whether by reading the state they left behind or by reading the results they returned. Either way, the grade assumes that each call did what its interface said, and that assumption sits underneath every leaderboard position and model-selection decision built on such a benchmark's number.

We set out to test that interface-to-implementation-to-state-transition contract directly, for every mutating tool a benchmark ships, and three challenges make that hard. \textbf{No contract exists to check against.} One must be authored from the tool's own advertised surfaces, and a check built on a surface that is itself wrong inherits the error. \textbf{Simplification is not defect.} A simulated environment is deliberately simplified in ways its maintainers consider harmless, so telling a disclosed simplification from an undisclosed one needs a principled rule, not a maintainer to ask. \textbf{A violation does not name the scores it reached.} That requires tracing the defect through the benchmark's own evaluation code to the fields it reaches.

That untested contract is also a data-quality problem: benchmark scores are a published data product the field mines and reuses in leaderboards and model-selection decisions, the context the data-quality dimensions literature judges a product against \cite{wangstrong96}. This paper audits that provenance, formalized for a query by dependency-analysis research \cite{bunemantan01} and surveyed as a data-management problem in its own right \cite{simmhanplale05}. A defect in that instrument is, unlike noise, present on every rerun, so the exposure it creates travels with the number into every downstream use. What that exposure could amount to is what score-at-risk bounds, without asserting that any verdict changed.

This paper meets those three challenges directly. For each mutating tool we author an executable contract from the tool's own advertised surfaces (docstring, schema, prompt text, return strings). We then check the implementation and state transitions against that contract with a static and dynamic checker, and trace which task verdicts depend on the state the defect corrupted, tagging each bound by the evaluator basis that produced it. \section{Related Work}
\label{sec:relwork}

Three literatures border this audit, and each takes the tool layer on trust: the benchmarks that grade by the state a call leaves, the work that verifies completion against that state, and the contract-checking lineage whose technique we borrow for a different target.

\subsection{\textbf{How Agent Benchmarks Grade Tool-Using Tasks}}

Agent benchmarks that score tool-calling episodes almost uniformly grade by inspecting the state a call leaves behind. WebArena \cite{webarena24}, AppWorld \cite{appworld24}, OSWorld \cite{osworld24}, and AndroidWorld \cite{androidworld25} grade by post-episode state, database rows, files, or device configuration, not the agent's claim of success. tau2-bench \cite{tau2bench25} compares gold and predicted final database state or per-task assertion functions; AgentDojo \cite{agentdojo24} inspects the environment's own post-call state. This line of work treats the tool layer as the trusted instrument doing the measuring. AgentFairBench makes the same move for fairness measurement: fairness is still assessed by grading answers while agents increasingly act, and it scores those actions with metrics including a tool-invocation disparity \cite{agentfairbench26}. Such measures read the tool layer directly, inheriting whatever it gets wrong.

\subsection{\textbf{Verifying That a Task Actually Completed}}

Verifying completion against recorded state is itself well established, so a tool-layer audit has to say what it adds. Three recent works come closer. Agent-Diff \cite{agentdiff26} defines a ``state-diff contract'': success is an expected state delta, read from a replica API's before-and-after state. Gao and Zhou \cite{evidencebounds26} instead audit the outcome check itself: a task asking whether a shipping address changed, checked only by whether the agent clicked ``Save,'' shows a success criterion can accept a superficial proxy for the change it certifies. Advani \cite{falsesuccess26}, accepted to the FAGEN workshop at ICML 2026, compares agents' own completion claims against tau2-bench's and AppWorld's recorded state, showing LLM judges are unreliable arbiters of the gap. Each treats the state-writing layer as trusted: the replica API, the audited checkers, and tau2-bench's and AppWorld's own environment, respectively. \textit{This literature grades the agent using the benchmark's tool as ground truth, whereas we grade the tool}, re-executing it against its own declared preconditions, arguments, and postconditions. A construct-validity review of 445 LLM benchmarks \cite{constructvalidity25} sits outside this judgment-call genre: a tool either honors its declared contract or not, checked against state snapshots rather than an expert's read.

\paragraph{A single-layer audit finds each layer consistent here} The tool defect and the grader design at the center of this study's central chain (\S\,\ref{sec:experiments}) are mutually consistent: the grader's gate condition is the tool's own fabricated success string. The tool therefore reports a write that did not happen, and the grader accepts it as evidence. BenchGuard's EVAL-MISMATCH and Tool-Veritas's reward-basis mismatch are the nearest grader-side categories, but neither schema has an entry for a success signal decoupled from state, so neither could report this instance whether or not it ran on the benchmark. Theirs asks whether the verdict matches the outcome, ours the provenance of the evidence, which is why Ungrounded Oracle (\S\,\ref{sec:prelim}) is a separate property. JudgeSense reports comparable evaluator-layer fragility under prompt rewording \cite{judgesense26}. AgentProp-Bench \cite{agentpropbench26} audits the same stack one layer up, measuring how often a corrupted parameter reaches a wrong final answer and reporting agents that assert tool results they never obtained: Phantom Effect from the agent's side. Table~\ref{tab:disposals} names the six closest collisions inside this boundary. Five leave the tool's own implementation unexamined and trusted; the sixth is a temporal non-overlap.

\subsection{\textbf{Contract Inference, API Oracles, and the Testing Lineage}}

Contract checking and oracle machinery are mature for specifications and implementations in general, and none of it targets the tool-to-agent boundary. Design by contract with runtime verification is decades old \cite{jcontractor05}, \cite{jass01}, and contract inference, oracle languages and invariant detection cover the surrounding ground: pointer-state API contracts \cite{contract26}, an executable contract language \cite{icepick26}, REST invariants \cite{agora25}, frame specifications \cite{frames25}, and contracts for stateful modules \cite{cogent23} and deep-learning APIs \cite{dlcontract23}. Our Ignored Argument and Partial Effect rules are metamorphic relations in all but name \cite{segura18}, \cite{segura16}, \cite{chen18}, and stateful sequence exploration is established for REST APIs \cite{restler19}, \cite{godefroid20}.

A second line applies that same contract vocabulary to agents and benchmarks directly, but keeps the tool implementation trusted and tests something else instead. \cite{toolgate26}, \cite{abc26}, \cite{contract2tool26}, \cite{contractbench26} check an agent against a contract while trusting the contract; we invert that direction. The 34-fault taxonomy \cite{faulttaxonomy26} assumes the contract correct, the inverse of our object. BetterBench \cite{betterbench24} and UTBoost \cite{utboost25} audit a layer above the tool body, and Kapoor et al. \cite{kapoor24matter} raise the concern as general practice rather than as a taxonomy; PolDet \cite{gyori15} and iDFlakies \cite{idflakies19} anticipate Reset Leak via a comparable oracle, narrowing its novelty to target rather than technique. Recent benchmark work names our symptom while auditing nothing \cite{liveclawbench26}.

\section{Notations and Preliminaries}
\label{sec:prelim}

A benchmark tool is not application code that happens to be simulated: it is the write path of a measuring device. A defect in one enters a published number silently and on every rerun, rather than filing an issue. The deterministic evaluators surveyed in \S\,\ref{sec:relwork} read what the tool layer produced, whether as stored state or as the result a call returned, so a defective tool's output is inherited by any gate reading it. Consistency between a broken tool and its grader is not validity, and the tool layer needs its own audit.

\paragraph{The tuple, and the defect taxonomy} Every defect class this paper checks for is defined over the tuple \texttt{(pre, post, args, result)}: the canonical state snapshots before and after a call, the call's arguments, and its return value. Table~\ref{tab:taxonomy} defines six such classes, each an executable checker rule typed at the tool boundary; prose descriptions are glosses, the rule is the definition. All six were carved from the tau2-bench and MedAgentBench anchor findings before the other two were audited, so they fit those defects by construction, and the typing is a checking discipline, not a partition: Finding 5 trips Ignored Argument and Phantom Effect on one call.

Four of the six classes are field-observed in shipped benchmarks (\S\,\ref{sec:experiments}). Ignored Argument was mutation-only until the third and fourth benchmarks, and is now the most common class, with four instances. \S\,\ref{sec:experiments}'s open-world escape rate measures what that construction leaves uncovered rather than closing it.

\paragraph{Result-state disagreement is a signal, not a class} The Ignored Argument rule is deliberately state-only, since a conjunctive rule would miss AgentDojo's \texttt{reserve\_car\_rental}: it discards \texttt{end\_time} from state while interpolating it into the success string (\S\,\ref{sec:experiments}, Finding 6). A result varying with an argument whose state effect is absent is only an aggravating signal on the finding it accompanies.

\paragraph{The benign-simplification principle} The strongest objection a maintainer can raise is that these are intentional simplifications of a simulation that never claimed fidelity. Telling that case from an undisclosed divergence, the second challenge of \S\,\ref{sec:intro}, needs a criterion rather than a case-by-case judgment call, stated once and applied uniformly:

\begin{quote}
A simplification is benign exactly when it is advertised. The defect is never the simplification; it is the undisclosed divergence between what the interface tells the agent and what the implementation does.
\end{quote}

Three consequences follow. First, tau2-bench's own maintainers already draw this line: at \texttt{airline/tools.py:689} they advertise a deferred flight-database update where the agent can see it, so the checker does not flag it. At line 367, by contrast, they only log the omission in a warning the agent never sees, so the checker flags it. Second, either side of a divergence may be repaired, fixing a docstring as completely as fixing code; \S\,\ref{sec:experiments} counts such a response as a resolved finding. Third, the advertised surface is the right baseline: the agent's behavior is the measured quantity, scoped to \textbf{agent-side measurement validity}, audited throughout, not \textbf{consumer-side label validity}. That alternative is declined because a metric name has no fixed audience to check a claim against, where agent-visible text is a discrete artifact. The line-689 update is a true negative because the agent sees it, whether or not any score consumer does, except where MedAgentBench forces it. There, a design disclosed in a paper and on no surface the agent reads is flagged by the same rule that clears line 689 (\S\,\ref{sec:intro}, \S\,\ref{sec:experiments}).

\paragraph{One evaluator-layer property, kept outside the taxonomy} MedAgentBench's write graders exhibit a property we name Ungrounded Oracle. An oracle is whatever decides that a check passed; this one decides a state change by reading the actor's claim rather than the state. Field-observed in \S\,\ref{sec:relwork}, it is not a seventh class: the six classes are typed over \texttt{(pre, post, args, result)} at the tool boundary; oracle grounding is typed over grader source code instead. \S\,\ref{sec:experiments} emits it as a per-task classification.

\subsection{The Contract Specification}

Every contract clause cites the provenance of the advertised surface it operationalizes: file, line, and a verbatim quote checked at build time. Clauses fall into three grounding tiers: \textbf{agent-visible} text (docstring, schema, prompt template, tool return, README, external standard); \textbf{maintainer-annotated} text (a comment, log line, or TODO) no agent ever sees; and \textbf{inferred} semantics we assigned ourselves. Only agent-visible clauses are headline-eligible (\S\,\ref{sec:prelim}); the other two tiers are reported separately, never folded into a headline count. The benign-simplification principle of \S\,\ref{sec:prelim} governs contract authoring too: a documentation fix resolves a finding as completely as a code fix (\S\,\ref{sec:experiments}). The checker also knows when not to fire: tau2-bench's deferred flight-database update and its non-enforcement of cancellation eligibility are both true negatives our test suite exercises. Contract authoring is itself measured by two annotator sets under a pre-committed probe corpus, a sensitivity analysis reported in \S\,\ref{sec:experiments}.

\subsection{The Conformance Checker}

The checker's static and dynamic halves are laid out in Fig.~\ref{fig:pipeline}; UNTESTABLE stays in every denominator this paper reports, and the share is large: 96 of 180 clauses on tau2-bench, 11 of 60 on AgentDojo, 4 of 27 on MM-ToolSandbox. tau2-bench, AgentDojo, and MM-ToolSandbox run through adapters as subprocesses; MedAgentBench has no adapter and is checked statically (\S\,\ref{sec:intro}). All six defect classes now have a real code path, but four did not until a post-freeze mutation sweep exposed the gap. Reset Leak and Invariant Break verdicts, 35 frame clauses, and 17 of 19 tau2 contracts were silently never dynamically exercised; the gap was fixed at the cost of one disclosed refreeze cycle (\texttt{checker-freeze-v1} to \texttt{checker-freeze-v2}, detailed once under Threats). Adapter mechanics are in the artifact.

\subsection{Score-at-Risk as a Provenance Trace}

The paper's central deliverable is not a violation count but a provenance trace run backwards: given a confirmed defect, which task verdicts could have been computed on state that defect corrupted. It asks of a score what dependency analysis asks of a query result: which inputs it depended on \cite{bunemantan01}. \texttt{analysis/score\_at\_risk.py} performs the trace over the 1,208 rows in \texttt{report/score\_at\_risk.jsonl}, no model in the pipeline; a \texttt{-{}-verify} flag re-derives every row from the same pinned inputs and diffs it against the file on disk, checking reproducibility rather than claiming it. Three static steps:
\begin{enumerate}
\item \textbf{Defect to field.} From a contract's VIOLATES clause, the predicate's compiled abstract syntax tree, never its source string, yields the state paths the tool should have written and did not, or wrote unconditionally when a precondition should have blocked the write.
\item \textbf{Field to evaluator.} The benchmark's evaluation code is parsed the same way, by AST rather than pattern match, for the state paths it reads, and each read site is classified by provenance, live simulator state or agent transcript.
\item \textbf{Evaluator to tasks.} Every task whose verdict depends on a field in that intersection is enumerated from the benchmark's pinned task-definition file, exhaustively.
\end{enumerate}

Every at-risk figure carries a basis tag and is never pooled across bases; \S\,\ref{sec:experiments}'s detector-validation arm pools toy and real sites by design and is exempt. Reporting dimensions separately rather than as a single aggregate exposes failures an aggregate hides, a discipline RISED applies to clinical decision support, where reliability can pass while inclusivity and sensitivity fail \cite{rised26}. The bound runs in one direction only: at-risk is an over-approximation of misgrading via the state-dependency mechanism, holding only where the oracle is state-grounded. It says a verdict could have been computed wrong because its evaluator reads a field the defective tool controls, not that the verdict was wrong. \S\,\ref{sec:experiments} reports the per-benchmark results of applying this trace, including whether the bound is vacuous on a drawn sample.

\subsection{Baselines and Reference Points}

A defect class none of the audits we survey checks for has no shared-task competitor, so we report four comparison points instead. \textbf{(1) Incumbent practice: manual source audit.} Table~\ref{tab:findings}'s Surfaced-by column shows seven of eight findings were found by a person reading source; the checker discovered one statically and reproduced three of the four headline cells dynamically. \subsection{Evaluation Metrics}

This paper's evaluation vocabulary comes from mutation testing: inject a synthetic fault and check whether it is caught, treating surviving (``live'') mutants as a lower bound on what a contract misses \cite{jiaharman11}. The pre-registered plan fixes, before any mutant existed, what each arm can license (\texttt{experiments/detector\_analysis\_plan.md}, tag \texttt{checker-freeze-v1}, commit \texttt{9dacc79}). The closed-world arm licenses ``the checker detects violations of the clauses we wrote,'' never ``tool-contract defects''; the open-world arm licenses only a lower bound on the taxonomy's incompleteness, never coverage. Every rate below is a design-effect-adjusted Wilson lower bound (Kish design effect, Rao-Scott one-way ANOVA ICC estimator, \S\,5 of the plan) with its effective denominator beside it. Toy-domain numbers are reported for debugging and never enter a headline; the headline is real-tools recall only.

Steps 2 and 3 do not run: AppWorld-tier scenarios exercising this tool are graded inside the \texttt{appworld} package, which this project cannot clone. Table~\ref{tab:scoreatrisk}'s row reads \texttt{not\_computable\_appworld\_unreachable}, not a zero: a null population is data about what a static, offline audit can reach, not a claim that no task is at risk.

Table~\ref{tab:recall} reports recall by operator, each named for the class it injects. It is low throughout, and a post hoc diagnostic, \texttt{experiments/decompose\_closed\_world\_misses.py}, traces why. Of all 33 real-tool misses, the taxonomy itself owns 2 (\texttt{clause\_gap}), the frozen probe corpus owns 29 (\texttt{probe\_corpus\_unreachable}, never driving the mutated path into an observable state), and the remaining 2 are \texttt{probe\_gap} and \texttt{target\_not\_found} (detail is in the artifact). M-INVAR's 0.000 reads as ``no probe ever reached a mutated invariant path,'' not ``the checker cannot detect invariant breaks.'' M-RESET has no real-tool site to draw at all: no tool-implementation file in the four benchmarks audited here defines a state-restoring function, so the honest report is ``no data,'' not a rate of zero. Biconditional success (the mechanism M-PHANTOM depends on) is opt-in per contract, adopted on 18 of 19 tau2-bench, 1 of 7 AgentDojo, and 0 of 5 MM-ToolSandbox contracts; where not adopted, Phantom Effect cannot fire: a second reason M-PHANTOM's recall sits at 0.359.

\paragraph{Precision} The checker raised zero false positives against any injected mutant in the closed-world arm, across a pooled toy-plus-real sample of 25 flags (TP=25, FP=0; 24 semantics-preserving controls scored alongside). Precision is therefore $\geq$0.867 at the Wilson lower bound. This denominator is mutation-arm flags only; it says nothing about the field findings above, which were confirmed by direct source reading, not by this count. This number licenses nothing about recall, and unlike the AGORA+ reference point it structurally cannot false-positive against a clause it never wrote. That pooled sample also is not the pre-registered one: only M-PRECOND and M-IGNARG met the $\sim$25-per-class target, counting real and toy sites together, unlike the recall table's real-tool-only n-drawn column of 7 and 21 above. The shortfall for the rest is detailed under Threats.

\paragraph{Open-world escape rate, toy} cosmic-ray scored 368 mutations across 4,048 (mutation, tool) pairs; 229 were behaviourally live, and the checker missed a Wilson lower bound of 0.956 of them (point estimate 0.983). Those escapes decompose as 119 of 225 tracing to a clause the taxonomy never wrote, 86 to a clause whose probes never drove the tool into the exposing state, and 20 to the checker crashing before evaluation. Only the mechanical declared-volatile-field rule ran in this automated pass, making 0.956 conservative toward overstating the checker's blindness: a lower bound on the taxonomy's incompleteness, not evidence against the closed-world numbers above.

\paragraph{tau2-telecom produced no usable escape rate} cosmic-ray scored 465 mutations across 2,325 (mutation, tool) pairs against the domain's five non-anchor tools, and zero were behaviourally live, so the escape-rate denominator is zero. The cause is the probe corpus, not the detector: its recorded-real-call component does not exist, and the two placeholder components fail tau2's entity-keyed checks before any mutation could show. A zero denominator is not evidence of a well-covered taxonomy; this arm is an open question. A precompute cache predating \texttt{checker-freeze-v2} had produced a more favorable v1 run (281 of 465 scored, 33 live, escape rate $\geq$0.325), not reported since whether those 33 live mutants were genuine or cache artifacts is unresolvable.

\paragraph{Evaluation impact: a null, not a gap} Two tau2-bench findings carry mechanically verified one-hunk patches: cancelling a reservation leaves \texttt{seats\_after} at 0 unpatched and restores it to 3 patched; refuelling a suspended line succeeds unpatched and raises \texttt{ValueError} patched. Ten trajectories were replayed from each finding's own gold reference solution, five per finding (seed 1, zero discarded). Agent trajectories were unavailable offline (no model credentials), so gold references were substituted instead, a disclosed deviation from the pre-registered plan (\texttt{experiments/analysis\_plan.md} \S\S\,4--5). This substitution strengthens, not weakens, the determinism claim, since no model selects the trajectory either. All ten land in a single outcome cell (at risk, not exercised), and zero trajectories trip either trigger predicate, so zero verdicts flip. For F3 (airline \texttt{cancel\_reservation}), no flip was possible by construction: gold-run and agent-run state execute the identical, still-defective tool. For F2 (telecom \texttt{refuel\_data}), a flip was possible in principle and did not occur, because no gold trajectory calls the tool on an inactive line, and all 1,120 telecom tasks whose gold actions call it issue the same one. Per the pre-registered interpretation, this is a finding about conditional validity, not a null result: the score is correct today because no gold trajectory takes the broken path, and nothing in the benchmark prevents an agent from doing so. What that does and does not license is taken up under Threats. Full experiment detail is in the artifact.

\paragraph{Sensitivity analysis: contract-authoring agreement} Two annotator sets wrote contracts for the same six tools against one pre-committed probe corpus. Both are agent sessions on one model family and only B wrote blind, so what this measures is whether a sentence turns into the same predicate twice, not whether two people would agree. This is evidence of stability in sentence-to-predicate translation under one-way blindness, not independent human judgment. The two sets are compared against a shared, pre-committed probe corpus across six tools, over comparable clause pairs on successful calls only. This scoping rule lands in the same commit as the result (\texttt{dee7170}) rather than in the protocol itself (\texttt{fc776b6}), disclosed here as applied post hoc. It drops \texttt{refuel\_data} to n=2 of 9 probes and \texttt{reserve\_car\_rental} to n=2 of 11 on most pairs. The blind stratum agrees on 98 of 98 probe comparisons across 16 clause pairs and four of five blind tools; the fifth, \texttt{venmo\_social}, contributes zero comparable pairs, a segmentation artifact that also cost it Finding 7's own anchor \texttt{arg.sort\_by}. Four tools needed hand-built witness probes, disclosed before any outcome was inspected, and the sixth, \texttt{cancel\_reservation}, forms a separate contaminated stratum (Annotator B had read a worked example beforehand), never pooled with the blind result. One finding flips within the blind stratum and is not among the 98, since the comparability filter excludes its clause pair. The protocol's own rule counts UNTESTABLE against anything as a disagreement rather than a skip, so the unfiltered count is 98 of 99. \texttt{reserve\_car\_rental}'s \texttt{arg.end\_time} is VIOLATES under A and UNTESTABLE under B, a missing ISO-string annotation in B's contract rather than a semantic disagreement (mechanism in the artifact).

\subsection{Threats to Validity}

\textbf{Taxonomy coverage.} Six classes are not the space of possible defects. The toy-domain mutation arm measures how much escapes them, and \S\,\ref{sec:experiments} reports that bound together with the clause-level decomposition of what got past.

\textbf{Real-benchmark escape rate.} The equivalent real-benchmark run produced no usable escape rate at all, for the reason \S\,\ref{sec:experiments} gives with the counts: the probe corpus rather than the detector.

\textbf{Sample size shortfall.} Four of six operators fall short of the pre-registered target because the corpus is structurally small, not because of a scoring choice (\S\,\ref{sec:experiments}). Achieved N is reported beside the target throughout, never absorbed into a rate.

\textbf{No real-tool reset site.} Reset logic lives in the adapter layer, which rebuilds environments wholesale, so none of the four benchmarks audited here colocates reset with its tools. M-RESET therefore has no data rather than a recall of zero.

\textbf{Subprocess exception boundary.} The subprocess boundary absorbs exceptions the checker never sees, and whether that matters is unverified. A toy-domain bug in the closed-world v2 run showed this directly: an adapter's \texttt{invoke()} caught only its own declared error type, so a probe past a deleted guard drove the tool into code assuming the check held. The raw exception then aborted the mutant rather than registering as a violation. The same boundary sits between the checker and every real adapter, swallowing exceptions before the harness can classify them; an absorbed crash's detected-vs-silent status is unchecked, bounding every real-tools recall number above.

\textbf{Replay covers gold behaviour only.} All 1,120 tasks whose gold actions call F2's tool issue one identical call, so five replays exhaust the gold solutions rather than sampling them (\S\,\ref{sec:experiments}). What the null cannot show is what an agent would do.

\textbf{Anchor-driven benchmark selection.} Benchmark selection is anchor-driven, not a sample of a population. tau2-bench and MedAgentBench entered this study because their defects were known before the four-benchmark protocol existed; AgentDojo and MM-ToolSandbox were added afterward to test whether the taxonomy generalized beyond the two anchors. No prevalence claim, what fraction of shipped benchmarks carry a defect class or how common Ignored Argument is, is supportable from four benchmarks chosen this way.

\textbf{Frame-grammar expressiveness gap.} The frame-path grammar cannot express one of its own most natural clauses. \texttt{spec/GRAMMAR-GAPS.md} records that no wildcard segment can exclude a single key, so a clause meaning ``no other reservation is modified'' cannot be written without colliding with the tool's own advertised effect on the reservation it changes. The shipped \texttt{cancel\_reservation} contract substitutes a weaker, expressible claim about an unrelated collection; the gap is a real coverage hole in the frame mechanism.

\textbf{Repository history limits.} Repository history cannot support every ordering claim this paper might like to make. \texttt{git init} ran on 2026-08-21, after most of the design work already existed, and the first commit imported the project as a single tree. A squashed import cannot demonstrate any pre-registration preceded the design decisions it was meant to freeze; the paper does not claim it does. What remains verifiable: \texttt{checker-freeze-v1} predates the first scored mutant, and \texttt{experiments/analysis\_plan.md} predates the first recorded trajectory, both checkable from commits after the import. The distinction is stated here rather than left for a reviewer to find (\texttt{PROVENANCE.md}).

\textbf{Disclosed refreeze cycle.} One refreeze is disclosed rather than folded into the numbers: \S\,\ref{sec:method} details four taxonomy claims a sweep against \texttt{checker-freeze-v1} found uncoded, all fixed before \texttt{checker-freeze-v2} scored any number above. Ranked by how much each could move the conclusions, the missing recorded-real-calls corpus matters most, the subprocess boundary's absorbed-exception ambiguity comes second since it bounds every recall number, and the anchor-driven selection third since it forecloses any prevalence claim.

% VI. CONCLUSION
% =======================================================================
\section{Conclusion}
\label{sec:conclusion}

This paper tested a layer the benchmark audits we survey do not reach: the tool implementation that produces what a grader reads, and so the provenance of every score built on it. Four benchmarks yielded verified defects across four of six executable classes, and the score-at-risk analysis traced what those defects could have cost in published verdicts, tagged by evaluator basis rather than pooled. None of this establishes how common such defects are: anchor-driven audits are existence proofs, not a survey, and an at-risk bound is a due-diligence flag, not a correction to any published score. Maintainers can act on it now: run a precision-favoring check against the tool layer, not only tasks and gold solutions; disclose every deliberate simplification on the surface an agent reads, not only in the paper that describes the benchmark, since on that surface an undisclosed one is indistinguishable from a bug. A benchmark's published numbers are a data product, and they are only as trustworthy as the layer those audits do not reach.
