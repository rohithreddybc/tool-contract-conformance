\begin{abstract}
Agentic benchmarks score an agent by executing tool calls against a simulated environment and reading the resulting state, assuming the tool did what its interface advertised. None of the audits we survey test that assumption; they inspect tasks, gold solutions, and graders, never the tool implementation. We author executable contracts from each tool's advertised surfaces (docstring, schema, prompt text, return value), check implementations and state transitions against those contracts, and trace which task verdicts depend on state a defective tool should have written. Across four benchmarks we confirm four headline-eligible tool-layer defect cells, from eight verified instances: three demonstrated dynamically and one, MedAgentBench's Phantom Effect, statically. Its write path is a no-op; no grader reads the record back, and where a write oracle exists at all it reconstructs the write from the agent's own transcript, gated on a success string the harness fabricates. Score-at-risk bounds are basis-tagged rather than pooled: an exact-field evaluator puts 1,135 of 2,285 tasks in tau2's full generated telecom file (not its own smaller published-evaluation subset) at risk, while a coarser whole-database-hash basis puts all 50 airline tasks at risk by construction. Detection on the mutation arm is precise ($\geq$0.867, zero false positives over 25 flags) but recall is weak at design-effect-adjusted Wilson lower bounds on real tools; an open-world mutation arm gives an escape rate $\geq$0.956 on a toy domain and an undefined rate, zero live mutants, on tau2. A pre-registered trajectory-replay check on ten gold trajectories exercises the defect zero times and records zero verdict flips.
\end{abstract}

\end{IEEEkeywords}

% I. INTRODUCTION

\section{Introduction}

Agentic benchmarks help decide which language models ship. A benchmark scores an agent by executing its tool calls against a simulated environment and reading the state those calls leave behind, assuming each call changed the world the way its interface said. That assumption is fragile: LiveClawBench names, as its motivating problem, that agent-benchmark mocks are commonly ``reduced to endpoint-level stubs that remove sessions, artifacts, state transitions, and downstream side effects'' \cite{liveclawbench26}. This is a prospective observation -- a reason to build higher-fidelity mocks -- not a measurement of which shipped benchmarks discard state transitions or what that costs their scores.

The loss can be total. MedAgentBench \cite{medagentbench25} evaluates language-model agents against a simulated electronic health record. Its harness handles every write request an agent emits in one branch of one function (\texttt{src/server/tasks/medagentbench/\_\_init\_\_.py}, lines 85--91 at commit \texttt{9926011}, abridged):

\begin{lstlisting}
elif r.startswith('POST'):
    try:
        payload = json.loads('\n'.join(r.split('\n')[1:]))
    ...
    else:
        session.inject({"role": "user", "content":
            "POST request accepted and executed successfully. ..."})
\end{lstlisting}

The payload is parsed into a local variable and never read again. No code anywhere in the repository performs the write: \texttt{git grep send\_post\_request} returns nothing at the pinned commit, with every \texttt{requests.post} call site in the client-side model transport [C1, C2 $\rightarrow$ \texttt{FINDINGS-VERIFIED.md}]. Every write action in this benchmark is a no-op that reports success to the agent.

None of the audits we survey can see this defect. Prior audits examine task instructions, gold solutions, evaluation scripts, environment configurations, graders, and judges \cite{benchguard26}, \cite{aba26}, \cite{toolveritas26}, \cite{safeaudit26}, but all stop one layer above the tool body and treat its implementation as ground truth: a grader inspecting sandbox state inherits any defect in the tool that wrote it, and reports agreement. None of them tests the interface-to-state-transition contract itself.

That untested contract is a data-quality problem of direct concern to this community. Benchmark scores are a published data product that the field mines, aggregates into leaderboards, and consumes in model-selection and deployment decisions, the context the data-quality dimensions literature judges a data product against \cite{wangstrong96}. This paper audits that provenance, tracing which verdicts depend on state a defective tool produced, the same dependency analysis provenance research formalizes for a query \cite{bunemantan01}. A defect in that instrument propagates into every downstream use of the score and, unlike noise, replicates perfectly: every rerun corrupts the measurement the same way.

This paper tests the interface $\rightarrow$ implementation $\rightarrow$ state-transition contract directly: for each mutating tool in a benchmark, we author an executable contract from the tool's own advertised surfaces (docstring, schema, prompt text, return strings), check the implementation and its state transitions against it, and trace the consequence: which task verdicts depend on that state. The contributions, in order of importance:

\begin{enumerate}
\item \textbf{Score-at-risk dependency analysis}: a static, per-benchmark bound on how many task verdicts depend on state a defective tool should have written, each row tagged with its evaluator basis (\S\,IV).
\item \textbf{Six executable defect classes}, defined as checker rules rather than prose (\S\,III). Phantom Effect, Partial Effect, and Reset Leak have no counterpart in any surveyed audit taxonomy.
\item \textbf{A provenance-bound contract format} in which every clause cites the advertised surface it operationalizes, and a static plus dynamic conformance checker (\S\,V, \S\,VI).
\item \textbf{Open-world-validated detection}: precision and recall against both taxonomy-shaped and off-taxonomy injected defects, under a pre-registered plan (\S\,VII).
\item \textbf{Confirmed findings}: four headline-eligible benchmark-class defect cells across four shipped benchmarks, from eight verified instances confirmed at a pinned commit, with coordinated disclosure to all maintainers (\S\,VIII).
\end{enumerate}

We did not invent design by contract, contract inference, or benchmark auditing: \S\,II concedes the checking technique and rests the paper's novelty on the target and the consequence for published scores.

One result shapes the whole argument: MedAgentBench's grader admits evidence only when followed by the literal success string its own defective tool fabricates, so the tool and the grader meant to catch it are mutually consistent, and five prior audits reported nothing (\S\,II, \S\,VIII).

\textbf{Contract inference and API oracles.} The checking technique here is not new. Design by contract with runtime verification is decades old \cite{jcontractor05}, \cite{jass01}; ConTract infers implicit API contracts over pointer state transitions (127 developer-confirmed inconsistencies) \cite{contract26}; IcePICK supplies a first-order executable contract language \cite{icepick26}; AGORA+ detects REST invariants at 80\% precision \cite{agora25}. Frame specifications formalize what a call must not change \cite{frames25}; contracts have been synthesized for stateful modules \cite{cogent23} and studied for deep-learning APIs \cite{dlcontract23}; our Ignored Argument and Partial Effect detectors are metamorphic relations in all but name \cite{segura18}, \cite{segura16}, \cite{chen18}, and stateful sequence exploration is established for REST APIs \cite{restler19}, \cite{godefroid20}. None examines an agentic benchmark harness, and none of their fault models contain a success signal decoupled from state, an effect applied without its inverse, or state leaking across episodes: in production a fault costs an outage; in a benchmark it costs a number nobody can tell is wrong. Kapoor et al.'s critique of agent-benchmark evaluation practice \cite{kapoor24matter}, BetterBench's benchmark-quality rubric \cite{betterbench24}, and UTBoost's test-oracle hardening for SWE-bench \cite{utboost25} likewise audit a layer above the tool body, none contesting this paper's novelty. PolDet \cite{gyori15} and iDFlakies \cite{idflakies19} anticipate Reset Leak specifically, detecting cross-test state leakage through a comparable oracle; Reset Leak is mutation-only with zero field instances here, so this precedent narrows its novelty to target rather than technique.

\textbf{The published numbers this defect sits under.} MedAgentBench's paper reports ``Action SR'', the write-task success rate, for all 12 evaluated models in its Table 3 \cite{medagentbench25}: it ranges 0.00\% to 71.33\%, best Gemini-1.5 Pro, two models at 0.00\%. The abstract headlines 69.67\% overall SR for Claude 3.5 Sonnet v2, a weighted blend of Query SR and this same Action SR, so the number the authors foreground inherits the construct-validity problem for its write half. We cite the arXiv table, read directly; the same paper is published in NEJM AI (vol.\ 2, iss.\ 9). The file containing the POST branch (\S\,I) is unchanged at our pinned commit, touched only once (January 2025), so every Action SR value was produced under an implementation in which no write occurs. The paper's own \S\,2.4.1 describes ``rule-based sanity checks to verify the correctness of the payload of POST requests'': the transcript-reconstruction mechanism \S\,VIII traces, gated on the fabricated success string. To be precise: the numbers are not wrong. They faithfully measure whether the agent emitted a well-formed POST request, not whether any clinical record changed, which is what ``action success rate'' is taken to mean by anyone reading a clinical-agent leaderboard.

\textbf{Why every prior audit missed it.} The tool defect (Finding 1) and the grader design (Finding 4) are mutually consistent: the grader's gate condition is the literal success string the harness injects at \texttt{\_\_init\_\_.py:91}, consumed by \texttt{extract\_posts}, so the tool reports a write that did not happen and the grader accepts exactly that report as its evidence. Audited alone, each layer is coherent: the tool returns what it says it returns, and the grader detects exactly what it looks for. BenchGuard's EVAL-MISMATCH category and Tool-Veritas's reward-basis mismatch plausibly cover the grader-side class of this defect, yet neither audit found this instance: single-layer audits are blind to cross-layer consistency defects by construction, insufficient when the layers agree with each other about a world that does not exist. We distinguish Ungrounded Oracle (\S\,IV) from Tool-Veritas's reward-basis mismatch: theirs concerns whether the verdict matches the outcome, ours the provenance of the oracle's evidence. JudgeSense reports a comparable evaluator-layer fragility: LLM judges are unstable under meaning-preserving prompt rewording \cite{judgesense26}.

\textbf{tau2-bench's numbers.} The pinned commit sits inside the code lineage producing tau2-bench's own published per-domain pass$^{1}$ results and the live public leaderboard, and both audited defects have been present, unpatched, across that span \cite{tau2bench25}, [\texttt{EXTERNAL-VERIFICATION.md} Task 2]. We claim no causal link from either defect to any specific published number: whether a task verdict depends on the affected state is exactly what \S\,IV's score-at-risk analysis answers, and asserting it from outside that analysis would overreach.

In sum, the checking technique is mature SE, the audit target is unoccupied, and the field's own newest benchmark work names our symptom while auditing nothing \cite{liveclawbench26}. What is new is the target, the defect classes it implies, the cross-layer blindness result, and the traced consequence for published scores.

\section{The Benchmark Tool Layer as a Measurement Instrument}

A benchmark tool is not application code that happens to be simulated. It is the write path of a measuring device. When production software has a defective write path, a service degrades and someone files an issue; when a benchmark tool has one, a published number is corrupted silently and reproducibly, and keeps being cited either way.

\textbf{Why the defect is invisible downstream.} Every deterministic evaluator in the surveyed literature reads state that tools wrote (tau2-bench's evaluator compares gold and predicted final database state [C11]), so a defective tool's output is inherited by any gate reading it (\S\,I, \S\,II). Consistency between a broken tool and its grader is not validity; the tool layer needs its own audit.

\textbf{The defect taxonomy.} Table~\ref{tab:taxonomy} defines six defect classes, each as an executable checker rule over the tuple \texttt{(pre, post, args, result)}: the canonical state snapshots before and after a call, the call's arguments, and its return value. The classes are typed at the tool boundary. Prose descriptions are glosses; the rule is the definition.

\begin{table*}[t]
\caption{Six executable defect classes.}
\label{tab:taxonomy}
\centering
\scriptsize
\begin{tabular}{@{}p{0.16\textwidth}p{0.62\textwidth}p{0.10\textwidth}@{}}
\toprule
Class & Checker rule (over \texttt{pre}, \texttt{post}, \texttt{args}, \texttt{result}) & Status \\
\midrule
Phantom Effect & success signal true $\land$ advertised effect delta absent & field-observed \\
Unenforced Precondition & precondition predicate false $\land$ (no error signal $\lor$ state mutated) & field-observed \\
Ignored Argument & post-state invariant under variation of an argument advertised as effective & field-observed \\
Partial Effect & $\geq\!1$ advertised effect predicate holds $\land$ $\geq\!1$ fails on the same call & field-observed \\
Invariant Break & environment invariant false after a legal call sequence & mutation-only \\
Reset Leak & snapshot after reset $\neq$ initial snapshot & mutation-only \\
\bottomrule
\end{tabular}
\end{table*}

Four of the six classes are field-observed in shipped benchmarks (\S\,VIII). \textbf{Invariant Break and Reset Leak have no field-observed instance anywhere in our findings}: they exist only as injected mutants, and every count in \S\,VII and \S\,VIII keeps that distinction visible. Ignored Argument was itself mutation-only until the third and fourth benchmarks were audited, and is now the most common class in the finding set, with four instances. \textbf{The taxonomy has an anchor lineage:} all six classes were carved from the tau2-bench and MedAgentBench anchor findings before the other two benchmarks were audited, so they fit those defects by construction, and \S\,VII's open-world escape rate measures that circularity rather than closing it.

\textbf{Result--state disagreement is a signal, not a class.} The Ignored Argument rule is deliberately state-only: an earlier conjunctive draft required both post-state and result invariant, but AgentDojo's \texttt{reserve\_car\_rental} discards \texttt{end\_time} from state while interpolating it into the success string, so that rule would never fire (\S\,VIII, Finding 6). A result varying with an argument whose state effect is absent is reported only as an aggravating signal on the finding it accompanies.

\textbf{The benign-simplification principle.} The strongest objection a maintainer can raise is that these are intentional simplifications of a simulation that never claimed fidelity. The answer is a criterion, stated once and applied uniformly:

\begin{quote}
A simplification is benign exactly when it is advertised. The defect is never the simplification; it is the undisclosed divergence between what the interface tells the agent and what the implementation does.
\end{quote}

Three consequences follow. First, tau2-bench's own maintainers already draw this line: at \texttt{airline/tools.py:689} they advertise a deferred flight-database update where the agent can see it, so the checker does not flag it, while at line 367 they only log the omission in a warning the agent never sees, so the checker flags it. Second, either side of a divergence may be repaired, fixing a docstring as completely as fixing code; \S\,VIII counts such a response as a resolved finding. Third, the advertised surface is the right baseline against the position that a benchmark owes fidelity only to itself: the agent's behavior is the measured quantity, conditioned on the interface text. That baseline is scoped to one audience: \textbf{agent-side measurement validity}, audited throughout; it says nothing about \textbf{consumer-side label validity}, whether the leaderboard reader, who sees no docstring, draws the right conclusion from a published score. The line-689 update is a true negative because the agent sees it; whether any score consumer does is untouched here except where MedAgentBench's construct-validity result forces it (\S\,II).

\textbf{One evaluator-layer property, kept outside the taxonomy.} MedAgentBench's write graders exhibit a property we name Ungrounded Oracle: its oracle for a state change reads the actor's claim, not the state. Field-observed in \S\,II, it is not a seventh class: the six classes are typed over \texttt{(pre, post, args, result)} at the tool boundary; oracle grounding is typed over grader source code instead. \S\,IV emits it as a per-task classification.

\textbf{Step 1, defect to field.} From a contract's VIOLATES clause, the predicate's compiled AST (never its source string) yields the state paths the tool should have written and did not, or wrote unconditionally when a precondition should have blocked the write. \textbf{Step 2, field to evaluator.} The benchmark's evaluation code is parsed the same way, by AST rather than pattern match, for the state paths it reads, and each read site is classified by provenance, live simulator state or agent transcript. \textbf{Step 3, evaluator to tasks.} Every task whose verdict depends on a field in that intersection is enumerated from the benchmark's pinned task-definition file, exhaustively.

\textbf{Every at-risk figure carries a basis tag, and the tags are never pooled.} tau2's airline domain grades \texttt{cancel\_reservation} by hashing the full database between gold and predicted runs (\texttt{toolkit.py:242-244}); any field a defective tool writes is, by construction, read by that mechanism, so all 50 airline tasks in that reward basis come back at risk. That measures the evaluator's coarseness, not the defect's reach, so Table~\ref{tab:scoreatrisk} tags it \texttt{whole\_state\_hash} instead of a sharper number. Telecom grades \texttt{refuel\_data} through per-task assertion functions instead; the intersection is exact: 1,135 of 2,285 tasks read a field the defective precondition lets through unconditionally, 1,120 on the specific written attribute (\texttt{exact\_field}) and 15 more on the containing collection alone (\texttt{collection\_only}). The 2,285 is the full generated task file (\texttt{data/tau2/domains/telecom/tasks.json}), not the roughly 114-task subset tau2-bench's paper evaluates; no mechanism here reconstructs it, so it is not computed. A single benchmark carries both bases on different tools; no project-wide percentage is stated, only per-basis counts, each with its own denominator. RISED makes the same argument: reporting five dimensions separately exposes cases where reliability passes by three orders of magnitude while inclusivity and sensitivity fail decisively \cite{rised26} --- an aggregate score hiding a dimension-level failure as a passing verdict hides a defective tool.

\textbf{The bound is a bound, in one direction only.} At-risk is an over-approximation of misgrading via the state-dependency mechanism, holding only where the oracle is state-grounded. ``Score-at-risk'' borrows value-at-risk's shape without its probability content: it is a static reachability over-approximation, not a probability distribution, and should not be read as one. It says a task's verdict could have been computed wrong because its evaluator reads a field the defective tool controls, not that the verdict was wrong, and nothing about failure modes outside that mechanism. \S\,VII checks whether the bound is vacuous on a drawn sample and finds that, on the trajectories it recorded, it is not exercised.

\textbf{Oracle grounding is a first-class output, not a footnote, because a naive field-intersection returns the wrong answer for MedAgentBench, in the wrong direction.} Its write graders reconstruct the intended write from the agent's own transcript, gated on Finding 1's fabricated success string (\S\,I, \S\,VIII) --- criterion contamination, in measurement terms: the criterion contaminated by the predictor it grades. Field intersection alone cannot see this: the grader-checked field and the field the tool should have written share a name, so a names-only rule would call nearly every one of the 300 cases at risk. Classification is computed per grader function by which routine it calls, transcript-reconstruction, live-state, both, or neither: of 300 write-tagged cases, 60 are graded unconditionally from the transcript, 90 read live state only to gate whether a write is required and then grade the write itself from the transcript, 150 have no write oracle at all, and zero are graded by reading the write back from FHIR state. Score-at-risk is undefined for the 60 and indeterminate for the 90, never zero, never inflated, a distinct verdict: ``oracle not state-grounded.'' The evaluator property is Ungrounded Oracle (\S\,III), now a result rather than an aside.

\textbf{The experiment frame need not nest inside the at-risk population, and for Finding 5 the two sets are disjoint.} The natural expectation (that a stricter selection rule, a task whose own gold solution invokes the defective tool, is always a subset of the field-dependency population) is wrong: \texttt{experiment\_frame\_subset\_of\_at\_risk} is computed, not asserted, and it is \texttt{False} for AgentDojo's Finding 5. \texttt{update\_scheduled\_transaction} is broken on every argument at falsy values (\texttt{amount} at \texttt{0}, \texttt{date}/\texttt{subject}/\texttt{recipient} at the empty string, \texttt{recurring} at \texttt{False}), but \texttt{recurring} is the one argument for which a falsy value is a legitimate advertised input, so it alone carries task risk here: four tasks' gold solutions call the tool but only to vary \texttt{amount} or \texttt{recipient}, so none of them lands in the at-risk set field dependency computes. The two sets share zero tasks. The one task whose oracle reads \texttt{.recurring}, \texttt{UserTask6}, reaches that field through a different, non-defective tool, \texttt{schedule\_transaction}, so it is at risk by field-dependency and outside the experiment frame by gold-invocation. Argument-specific defects make the two rules select different, non-nested populations: field dependency cannot see which argument a task exercises; gold-invocation cannot see which field the oracle reads; both are reported with their own denominators.

\textbf{MM-ToolSandbox reports what it can compute and nothing it cannot.} Step 1 identifies the \texttt{sort\_by} field \texttt{venmo\_social} drops (Finding 7). Steps 2 and 3 do not run: AppWorld-tier scenarios exercising this tool are graded inside the \texttt{appworld} package, which this project cannot clone. Table~\ref{tab:scoreatrisk}'s row reads \texttt{not\_computable\_appworld\_unreachable}, not a zero and not an omission. A null population is data about what a static, offline audit can reach, not a claim that no task is at risk.

% V. THE CONTRACT SPECIFICATION

\section{The Contract Specification}

Every contract clause cites the provenance of the advertised surface it operationalizes (file, line, and a verbatim quote checked against the pinned commit at build time) across three grounding tiers: \textbf{agent-visible} text (docstring, schema, prompt template, tool return, README, external standard) the agent was conditioned on; \textbf{maintainer-annotated} text (a comment, log line, or TODO) stating intended semantics no agent ever sees; and \textbf{inferred} semantics we assigned ourselves. Only agent-visible clauses are headline-eligible (a violation there corrupts the measurement, \S\,III), while the other two tiers are reported separately, never folded into a headline count: the paper's construct-validity firewall against the ``just our opinions'' objection. The benign-simplification principle of \S\,III governs contract authoring too: either side of a divergence may be repaired, a documentation fix resolving a finding exactly as completely as a code fix (\S\,VIII). The checker also knows when not to fire: tau2-bench's advertised deferred flight-database update and its advertised non-enforcement of cancellation eligibility are both true negatives our test suite exercises, the credibility anchor behind every VIOLATES verdict elsewhere in the paper.

Contract authoring is measured, not trusted, but the measurement is of a narrower thing than independent replication. Both annotator sets, A and B, are agent sessions on the same underlying model family, and only B authored blind. A already knew which tools carried confirmed findings; what follows is evidence of \textbf{stability of sentence-to-predicate translation under one-way blindness}, not of independent human judgment, and the paper claims no more than that. The two sets are compared extensionally against a shared, pre-committed probe corpus across six tools, over comparable clause pairs on successful calls only. The blind stratum agrees on 98 of 98 probe comparisons across 16 clause pairs, a span covering four of the five blind tools; the fifth, \texttt{venmo\_social}, contributes zero comparable pairs, because the blind annotator segmented the multiplexed tool into disjoint dispatch branches and never declared Finding 7's own anchor \texttt{arg.sort\_by}. That anchor is incomparable, not agreeing, itself a segmentation result about multiplexed tools. Four tools (\texttt{refuel\_data}, \texttt{cancel\_reservation}, \texttt{update\_scheduled\_transaction}, \texttt{venmo\_social}) needed hand-built witness probes, disclosed before any outcome was inspected, because the frozen corpus could not reach them. A sixth tool, \texttt{cancel\_reservation}, forms a contaminated stratum (Annotator B had read a worked example of this exact tool beforehand) and is reported separately, never pooled with the blind result. One finding flips within the blind stratum: \texttt{reserve\_car\_rental}'s \texttt{arg.end\_time} is VIOLATES under A and UNTESTABLE under B, because A's contract declares a \texttt{probe\_values} hint pinning the argument to parseable ISO strings and B's does not, so every probe B's contract can build fails inside \texttt{datetime.fromisoformat()} before reaching the tool's effect code, a missing annotation, not a disagreement about advertised semantics; both annotators independently flagged the underlying defect in their own notes. The full grammar, clause-authoring protocol, segmentation rules, and worked-example detail are in the artifact.

\textbf{AI-use disclosure.} Both annotator sets above, and the numeric analyses of \S\,IV, \S\,VI, and \S\,VII, were produced by agent-run scripts and sessions, disclosed here per IEEE's policy on generated content.

% VI. THE CONFORMANCE CHECKER

\section{The Conformance Checker}

The checker has a static half (five AST-only checks that flag candidate sites for a person to read) and a dynamic half that produces verdicts: snapshot a fresh environment, invoke the tool, snapshot again, and evaluate every clause against the resulting \texttt{(pre, post, args, result)} tuple, resolving to CONFORMS, VIOLATES with a minimal witness, or UNTESTABLE with a reason code; UNTESTABLE stays in every denominator this paper reports. tau2-bench, AgentDojo, and MM-ToolSandbox run through adapters as subprocesses; MedAgentBench has no adapter and is checked statically (\S\,I). All six defect classes now have a real dynamic or static code path, but four of them did not until a post-freeze mutation sweep exposed the gap. Reset Leak and Invariant Break verdicts, 35 frame clauses, and 17 of 19 tau2 contracts were silently never dynamically exercised. All four are fixed, at the cost of one disclosed refreeze cycle (\texttt{checker-freeze-v1} to \texttt{checker-freeze-v2}). Adapter mechanics, the subprocess boundary, and the remaining frame-path expressiveness gap are in the artifact.

This denominator is mutation-arm flags only; it says nothing about the field findings of \S\,VIII, which were confirmed by direct source reading, not by this count. This is the strongest number in the section and licenses nothing about the recall figures above: a detector that never lies about what it catches can still catch very little of what it should. For context, AGORA+ reports 80\% precision on REST invariant detection \cite{agora25}; this checker's precision sits above that figure, though its design structurally cannot false-positive against a clause it never wrote, an asymmetry the comparison does not correct for.

The rest are the plan's \S\,8 no-reuse refreeze rule meeting a structurally small pool, not a scoring shortfall: each remaining operator's real-tool site pool was small enough that the first freeze already drew most or all of it, and the second freeze either drew what was left or, for M-INVAR and M-RESET, fell back to rescoring the first freeze's own sites against the second freeze's checker, the one documented exception to the no-reuse rule. The full per-operator pool table is in the artifact.

\textbf{One refreeze cycle.} The numbers above are scored under \texttt{checker-freeze-v2} (commit \texttt{5824376}), not the first freeze: a mutation sweep against \texttt{checker-freeze-v1} found four taxonomy claims the checker had been carrying as closed with no code behind them, detailed in \S\,VI, and the checker was refrozen before any number here was scored.

\textbf{Open-world escape rate, toy.} cosmic-ray scored 368 mutations across 4,048 (mutation, tool) pairs; 229 were behaviourally live, and the checker missed a Wilson lower bound of 0.956 of them (point estimate 0.983), decomposed as 119 of 225 escapes tracing to a clause the taxonomy never wrote, 86 to a clause whose probes never drove the tool into the exposing state, and 20 to the checker crashing before evaluation. Only the mechanical declared-volatile-field rule ran in this automated pass (the interface-invisibility and second-annotator rules need a human annotator and are in the artifact), making 0.956 conservative toward overstating the checker's blindness. Per the committed framing, this is a lower bound on the taxonomy's incompleteness, not evidence against the closed-world numbers above.

\textbf{tau2-telecom produced no usable escape rate.} cosmic-ray scored 465 mutations across 2,325 (mutation, tool) pairs against the domain's five non-anchor tools, and zero were behaviourally live, so the escape-rate denominator is zero. The cause is the probe corpus, not the detector: its recorded-real-call component has no artifact anywhere in the project, and the two components that do exist are type-generic placeholders that fail existence checks on tau2's entity-keyed tools and raise before any mutation could show (detail in the artifact). A zero denominator is not evidence of a well-covered taxonomy; this arm is reported as an open question, not a result. A precompute cache predating \texttt{checker-freeze-v2} had already produced a more favorable v1 run on this arm (281 of 465 scored, 33 live, escape rate $\geq$0.325); it is not reported as a result, since whether those 33 live mutants were genuine or stale-cache artifacts is now unresolvable, and the run is disclosed rather than dropped in the direction that would have flattered us.

\textbf{Evaluation impact: a null, not a gap.} Two tau2-bench findings carry mechanically verified one-hunk patches: cancelling a reservation leaves \texttt{seats\_after} at 0 unpatched and restores it to 3 patched; refuelling a suspended line succeeds unpatched and raises \texttt{ValueError} patched. Ten trajectories replayed from each finding's own gold reference solution (five per finding, seed 1, zero discarded for infrastructure failure) all land in a single outcome cell: at risk, not exercised. Zero trajectories trip either finding's trigger predicate, and zero verdicts flip. For F3 (airline \texttt{cancel\_reservation}), no flip was possible by construction: the evaluator compares gold-run state against agent-run state, and both sides execute the identical, still-defective tool, so the symmetric-oracle structure absorbs the defect regardless of the exercise rate. For F2 (telecom \texttt{refuel\_data}), a flip was possible in principle and did not occur, because none of the five sampled gold trajectories calls the tool on an inactive line. Per the pre-registered interpretation (\texttt{experiments/analysis\_plan.md}), this is a finding about conditional validity, not a null result: the score is correct today because no agent happens to take the broken path, and nothing in the benchmark prevents one from doing so. N=5 per finding is provisional. F3's affected population of 7 tasks makes it near-exhaustive; F2's population of 1,120 does not (\S\,IX). The null therefore cannot separate a defect latent under every gold trajectory from one an undersized sample missed. The experiment design, the full per-finding outcome-cell table, and the evaluator-basis exercise/flip breakdown are in the deposited artifact.

\section{Threats to Validity}

\textbf{The taxonomy is not the space of possible defects, and the open-world arm measures the gap rather than closing it.} \S\,VII's open-world arm on the toy domain found the checker missing a Wilson lower bound of 0.956 of behaviourally live mutants, decomposed there into unwritten-clause, unreached-state, and checker-crash causes. Six classes, even perfectly detected, would still miss most of what an operator with no knowledge of the taxonomy can break, a limitation the paper's own numbers state.

\textbf{The equivalent real-benchmark run produced no usable number at all, and the absence is reported rather than hidden (\S\,VII).} cosmic-ray's 465 mutations against tau2-telecom's five non-anchor tools yielded zero behaviourally live mutants, so the escape-rate denominator is zero; the cause is the probe corpus, not the checker. The same missing artifact (no production caller ever supplies a recorded real call) also explains the \texttt{reserve\_car\_rental} agreement flip (\S\,V) and 29 of \S\,VII's 33 real-tool misses, making a recorded-real-calls corpus this project's highest-value future work.

\textbf{Sample sizes fall short of the pre-registration for four of six mutation operators, and the shortfall is structural, not a scoring choice.} \S\,VII's achieved-N table shows only M-PRECOND and M-IGNARG meeting the $\sim$25-real-tool-site target; the rest exhausted a structurally small corpus under the plan's \S\,8 no-reuse refreeze rule. Achieved N is always reported beside the pre-registered target, never absorbed into a rate.

\textbf{M-RESET has no real-tool site at all} (\S\,VII): reset logic lives in the adapter layer, which reconstructs environments wholesale rather than repairing them in place, so only the toy domain colocates reset with its tools for the operator to enumerate. The honest report is ``no data,'' not a recall of zero; Reset Leak's field-observed count here is zero.

\textbf{The subprocess boundary absorbs exceptions the checker never sees, and whether that matters is unverified.} A toy-domain bug in the closed-world v2 run showed this directly: an adapter's \texttt{invoke()} caught only its own declared error type, so a probe past a deleted guard drove the tool into code assuming the check held, and the raw exception aborted the mutant rather than registering as a violation. The same boundary sits between the checker and every real adapter, swallowing exceptions before the harness can classify them; an absorbed crash's detected-vs-silent status is unchecked, bounding every real-tools recall number in \S\,VII.

\textbf{The agent-experiment sample is provisional at N=5 per finding} (\S\,VII), \textbf{and a null at that size proves less than it looks like it proves.} F3's affected population of 7 tasks makes 5 close to exhaustive; F2's population of 1,120 does not. Zero of ten trajectories exercising either trigger predicate cannot separate a defect latent under every gold trajectory from one an undersized sample missed.

\textbf{Benchmark selection is anchor-driven, not a sample of a population.} tau2-bench and MedAgentBench entered this study because their defects were known before the four-benchmark protocol existed; AgentDojo and MM-ToolSandbox were added afterward to test whether the taxonomy generalized beyond the two anchors. No prevalence claim, what fraction of shipped benchmarks carry a defect class or how common Ignored Argument is, is supportable from four benchmarks chosen this way. The four findings sets are existence proofs that the defect classes occur in shipped, audited artifacts, not a survey of frequency.

\textbf{The frame-path grammar cannot express one of its own most natural clauses.} \texttt{spec/GRAMMAR-GAPS.md} records that no wildcard segment can exclude a single key, so a clause meaning ``no other reservation is modified'' cannot be written without colliding with the tool's own advertised effect on the reservation it changes. The shipped \texttt{cancel\_reservation} contract substitutes a weaker, expressible claim about an unrelated collection; the gap is a real coverage hole in the frame mechanism, named here rather than hidden.

\textbf{Repository history cannot support every ordering claim this paper might like to make.} \texttt{git init} ran on 2026-08-21, after most of the design work already existed, and the first commit imported the project as a single tree. A squashed import cannot demonstrate any pre-registration preceded the design decisions it was meant to freeze; the paper does not claim it does. What remains verifiable: \texttt{checker-freeze-v1} predates the first scored mutant, and \texttt{experiments/analysis\_plan.md} predates the first recorded trajectory, both checkable from commits after the import. The distinction is stated here rather than left for a reviewer to find (\texttt{PROVENANCE.md}).

\textbf{One refreeze cycle is disclosed rather than folded into the final numbers.} \S\,VI details the four taxonomy claims a mutation sweep against \texttt{checker-freeze-v1} found uncoded, all fixed before \texttt{checker-freeze-v2} scored any number in \S\,VII. A framework reporting the sweep that found its own holes earns more trust than one presented as complete; the cost, one refreeze cycle, is stated plainly rather than absorbed into the total.

\textbf{Ranked by how much each could move the conclusions:} the missing recorded-real-calls corpus first (it explains the tau2 zero denominator, the agreement flip, and 29 of 33 misses); the subprocess boundary's absorbed-exception ambiguity second (it bounds every recall number here); and the anchor-driven benchmark selection third (it forecloses any prevalence claim).

\section{Conclusion}

This paper tested a layer no published benchmark audit reaches: the tool implementation that produces the state a grader reads. Four benchmarks yielded eight verified instances across six executable defect classes, four headline-eligible under a grounding rule that excludes what no agent ever saw. The score-at-risk analysis traced what those defects could have cost in published verdicts, tagged by evaluator basis rather than pooled into one number, and the open-world arm measured how much of the defect space six classes still miss. None of this establishes how common these defects are across agentic benchmarks generally: four anchor-driven audits are existence proofs, not a survey. Benchmark scores are published measurement data the field mines and reuses in leaderboards and model-selection decisions, and an instrument defect at this layer propagates into every downstream use of the number it produced. What this checker demonstrably delivers today is high-precision flagging, zero false positives across 25 mutation-arm flags, paired with a score-at-risk trace from a confirmed defect to the verdicts it could corrupt; coverage remains the open problem \S\,IX quantifies. A score consumer should read an at-risk bound as a due-diligence flag, never a correction to the published score. Maintainers can act now: run a precision-favoring check like this one against the tool layer itself, not only tasks and gold solutions, and treat a flag as cause to look, not to re-score. State every deliberate simplification on the surface an agent reads (a docstring, a schema, a returned string) because an undisclosed one is indistinguishable from a bug to the agent conditioned on it and to the grader scoring the result. Never let a grader's success condition be satisfied by a string the harness itself fabricates, the pattern that let a construct-validity failure survive five prior audits in this study's most clinically consequential benchmark. A benchmark's published numbers are only as trustworthy as the layer nobody has been checking.
